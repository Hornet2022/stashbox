## §0 一句话定位

> **听匣 —— 给眼睛减负、把内容消化交给 AI、把通勤时间变成深度阅读。**

用户在微信、抖音、网页看到任何想读但没时间读的内容 → 一键"丢给听匣" → 通勤路上用耳机听 AI 改写的"听感版本"。

不是 RSS / 收藏夹 / 笔记软件 / 知识付费 —— **是"内容消费的 AI 翻译机"**。

## §1 产品是什么

### 1.1 解决什么问题

**3 个核心痛点**（按用户访谈频率排序）：

| # | 痛点 | 量化描述 | 谁最痛 |
|---|---|---|---|
| 1 | **眼睛累** | 上班盯屏 8 小时，回家再读长文眼睛报废 | 25-40 通勤族（**60%** 用户）|
| 2 | **收藏=没读** | 收藏夹 800+ 篇，实际读完不到 10% | 知识工作者 / 学生（**30%**）|
| 3 | **碎片时间浪费** | 通勤 30-60 分钟刷短视频，刷完脑子更空 | 全职通勤族（**80%**）|

**一句话**：**用户在错的地方、用错的方式、消耗了不该消耗的时间。**

### 1.2 目标用户（4 类）

#### A. 知识工作者 / 通勤族（60%）

- **画像**：25-40 岁，IT / 产品 / 运营 / 媒体，月入 1.5w+
- **场景**：早晚通勤 30-60 分钟 + 午休碎片 15 分钟
- **痛点强度**：⭐⭐⭐⭐⭐
- **付费意愿**：¥19-39/月

#### B. 学生 / 自学者（20%）

- **画像**：18-28 岁，本科 / 研究生 / 留学
- **场景**：早晚通勤 + 图书馆往返 + 睡前
- **痛点强度**：⭐⭐⭐⭐
- **付费意愿**：¥9-19/月

#### C. 中年 / 退休族（5%）

- **画像**：50-70 岁，半退休
- **场景**：家务 / 散步 / 公园 / 睡前
- **痛点强度**：⭐⭐⭐
- **付费意愿**：低（兼容免费 + 大字号）

#### D. 自用 + 创作者（15%）

- **画像**：自媒体 / 写作者 / 行业研究者
- **场景**：素材库 + 内容二次创作
- **痛点强度**：⭐⭐⭐
- **付费意愿**：免费够用（种子用户）

**100 人内测目标分布**：A50 + B20 + C5 + D25

### 1.5 不做的事（6 条护城河）

- ❌ **不做内容生产**（不预设节目、不做播客）
- ❌ **不做社交**（不评论、不点赞、不关注）
- ❌ **不做电商**（不卖货、不带货）
- ❌ **不做 AI 生成内容**（用户给什么改写什么，不生成原创）
- ❌ **不做 Web 端播放器**（一期）
- ❌ **不做小程序 / PWA**（一期）

**为什么"不做"很重要**：护城河 = 知道**不做什么**。避免被同质化稀释。

#### 1.5.1 6 条护城河深度论证（v2.1 新增 · Hornet 2026-09-09 拍板）

**为什么补这节**：6 行 ❌ 评审委员会看完不知道"为什么不做"+"何时可反悔"+"做了会怎样"。这是 v2 §1.5 真正的"空洞"。

**❌ 1 · 不做内容生产**
- **不做定义**：不预设节目（不办"听匣精选"专栏）、不做播客（不录播客节目）、不做编辑（不挑内容）
- **为什么不做**：① 公众号生态已经够饱和（得到 / 樊登 / 凯叔），听匣做内容 = 跟用户争"权威"，用户不再信任 ② 内容生产成本极高（编辑团队 + 版权费），听匣一期就 5.5 人 ③ 内容生产 = 用户越来越少用听匣蒸馏自己的内容（都听官方精选）
- **模仿者陷阱**：如果听匣做了"精选专栏"，会立刻被得到 / 樊登 / 喜马拉雅碾压——他们有 10 年版权 + 千级编辑团队，听匣根本打不过
- **可反转点**：二期可以加"用户自建电台"功能（用户把自己蒸馏的 N 篇文章打包成私人电台），但**不做官方精选**——反转成本高（重新定位 + 营销重做）

**❌ 2 · 不做社交**
- **不做定义**：不评论、不点赞、不关注、不转发、不分享到朋友圈、不能@朋友、不能建群
- **为什么不做**：① 社交需要双端供给（既有读者又有作者），听匣只有读者侧 ② 评论需要审核 + 反垃圾，团队没人力 ③ 社交会导致"听匣 = 第二个微博"的心智混淆
- **模仿者陷阱**：如果听匣加了评论，立刻变成"AI 内容 + 评论" = 没人会真评论（因为内容是 AI 蒸馏的，不是创作者本人）
- **可反转点**：可以做"分享按钮"（分享给微信好友），但**不做平台内社交**——分享是动作不是功能
- **决策记录**：2026-09-09 Hornet 拍板"不做平台内社交，分享走系统"——平台内社交是飞书/微信的事，听匣不做

**❌ 3 · 不做电商**
- **不做定义**：不卖货、不带货、不开店铺、不开橱窗、不做会员积分商城
- **为什么不做**：① 电商需要供应链 + 客服 + 物流，听匣团队没基因 ② 卖货 = 听匣 = 第二个小红书/抖音电商，心智混淆 ③ 卖货会污染推荐算法（推荐"卖货文章"而不是"好内容"）
- **模仿者陷阱**：如果听匣加了"读完文章可一键购买文中提到的产品"，会立刻被小红书/什么值得买碾压——他们有 10 年电商基础设施
- **可反转点**：可以做"文中提到的实体书 → 跳转当当/京东"——但**听匣不参与交易**（跳转即走，流量不分润）
- **决策记录**：2026-09-09 Hornet 拍板"不做电商，导流可以，分润不要"——分润会让团队分心

**❌ 4 · 不做 AI 生成内容**
- **不做定义**：用户给什么改写什么，不生成原创、不续写、不扩写、不改写人称（不把"我"改成"小明"）
- **为什么不做**：① 生成内容 = 听匣 = "AI 写作工具" = 与 Notion AI / 秘塔写作猫同台竞争，听匣没优势 ② 用户对 AI 生成内容的信任度低（"这真的是文章作者说的吗？"） ③ L4 蒸馏的核心价值 = **忠实原文**，AI 生成会破坏这一信任
- **模仿者陷阱**：如果听匣做了"AI 续写文章"，立刻变成"AI 写手"——与豆包 / Kimi / 智谱同台，听匣没优势
- **可反转点**：可以做"AI 推荐相关文章"（基于用户历史推荐相似文章，不是生成）——但**不做内容生成**——这是 L4 蒸馏的本质
- **决策记录**：2026-09-09 Hornet 拍板"L4 蒸馏的本质是忠实原文，AI 生成 = 背叛产品灵魂"——这条不可反转

**❌ 5 · 不做 Web 端播放器（一期）**
- **不做定义**：不做网页版听匣（用户在浏览器打开 → 听蒸馏音频）
- **为什么不做**：① 一期团队 5.5 人，Web 端开发 + 维护成本高 ② Web 端后台播放体验差（Safari 后台限制 30 秒） ③ 通勤场景下用户在地铁/车里，手机优先
- **模仿者陷阱**：如果听匣做了 Web 端 = 第二个喜马拉雅网页版——喜马拉雅 Web 端体验已经很好，听匣没差异化
- **可反转点**：二期 CP2 评分 6.8/10 → 二期优先启动 Web 端（详见 §5.7.2）
- **决策记录**：2026-09-09 Hornet 拍板"一期不做 Web 端，二期 100 用户后启动"——二期决策有数据支撑

**❌ 6 · 不做小程序 / PWA（一期）**
- **不做定义**：不做微信小程序、不做 PWA（Progressive Web App）
- **为什么不做**：① 小程序后台播放限制（iOS Safari 后台 30 秒，安卓稍好但仍受限） ② 小程序缓存机制导致音频频繁丢失 ④ 微信生态对小程序的审核比服务号严
- **模仿者陷阱**：如果听匣做了小程序 = 第二个"微信听书"——腾讯自己的小程序生态比听匣有优势
- **可反转点**：iOS 解除后台限制后可重启 PWA（短期不会发生），但**D9 URL Scheme 已覆盖 90% 场景**——D9 + App + 服务号 = 用户已经够用
- **决策记录**：2026-09-09 Hornet 拍板"一期不做小程序，D9 + App + 服务号 三件套够用"——D9 是核心入口，不做小程序不等于没微信入口

#### 1.5.2 6 条护城河的可反转性矩阵

| 不做项 | 反转难度 | 反转成本 | 反转时机 |
|---|---|---|---|
| **❌ 1 不做内容生产** | 🟡 中 | 二期"用户自建电台"可加 | 二期可加（局部反转）|
| **❌ 2 不做社交** | 🟢 低 | 不做的无需反转 | 随时可加（但建议不加）|
| **❌ 3 不做电商** | 🟢 低 | 不做的无需反转 | 随时可加（但建议不加）|
| **❌ 4 不做 AI 生成内容** | 🔴 高 | 加上就破坏 L4 蒸馏本质 | **不可反转**（核心灵魂）|
| **❌ 5 不做 Web 端（一期）** | 🟢 低 | 二期启动即可 | 二期 100 用户后 |
| **❌ 6 不做小程序/PWA（一期）** | 🟢 低 | 二期启动即可 | 二期 1k 用户后 |

#### 1.5.3 决策记录

- **2026-09-09 Hornet 拍板**：6 条护城河中**只有 ❌ 4（不做 AI 生成内容）是核心灵魂**，不可反转；其余 5 条都是"一期不做 / 二期可加"——可反转性矩阵让评审看到"哪些是真护城河"
- **2026-09-09 承宇建议**：每个"不做"必须有"为什么不做"+"模仿者陷阱"——否则评审会问"为什么不做 X"
- **2026-09-09 待定**：❌ 1 + ❌ 5 + ❌ 6 的具体反转时机待二期 CP7 数据决定

## §2 长什么样

### 2.1 产品形态（C 端三件套 + D9/D10 入口）

| 形态 | 角色 | 一期占比 |
|---|---|---|
| **iOS + Android App** | **播放端（核心载体）** | 100% |
| **浏览器扩展**（Chrome / Edge / Safari）| 桌面端"加入"端 | 30% |
| **公众号 + 服务号** | 次要收集端（兜底）| 30% |
| **🟢 D9 微信"...→更多打开方式"** | **核心移动入口**（主力）| **60%** |
| **D10 ClawBot 插件** | 评估（CP6 启动后）| 待定 |

**关键结论**：**D9 = 听匣的生死线**——60% 用户通过它"加入"。

### 2.2 用户视角的 4 步完整流程

#### 步骤 1：用户在任何地方看到内容

场景 A：**微信文章**
```
用户读公众号 → 觉得值得深读 → 点击右上"..."→ 选择"更多打开方式"→ 听匣
```

场景 B：**抖音视频**
```
用户看到抖音 → 视频下方分享按钮 → 选择"听匣" → 自动 ASR 转写 + 蒸馏
```

场景 C：**任意网页**
```
桌面端：浏览器扩展一键加入
移动端：分享 → 听匣
```

#### 步骤 2：听匣"接住"

```
- App 已装：Deep Link 自动跳转 → 后台启动蒸馏任务
- App 未装：跳转应用商店 → 下载后任务自动恢复
```

#### 步骤 3：AI 蒸馏（用户不可见的"魔法"）

```
5-30 秒后：通知"✅ 文章已就绪"
80% 用户根本不会感知到"AI 在做什么"
```

#### 步骤 4：通勤收听

```
早晨 8:30 出门 → 戴上耳机 → App 自动播放最新加入
地铁里没信号？→ 已下载的音频继续播放
听了一半？→ 下次自动从断点继续
听完？→ 自动标记 + 通知"今日已消化 3 篇"
```

#### 2.3.6 屏幕状态矩阵（v2.1 增补 · Hornet 2026-09-09 拍板）

每个屏幕都需要设计**正常态 / 加载态 / 空态 / 错误态**4 种状态——下面是 5 个屏幕的状态矩阵。

**主屏 = 待听列表**：
| 状态 | 触发条件 | UI 表现 | 关键设计 |
|---|---|---|---|
| **正常** | 有 1+ 篇待听 | 顶部"正在听"卡片 + 下方列表 | 自动播放最新加入 |
| **加载** | 首次打开 / 下拉刷新 | 列表卡片显示骨架屏（3 个灰色占位卡）+ 顶部进度条 | < 500ms 不显示加载态，避免闪烁 |
| **空态** | 用户从未加入任何内容 | 大图标（📭）+ 文案"还没有任何内容"+ 主按钮"复制链接加入"+ 次按钮"浏览精选" | 不显示"立即收听"按钮（没东西可收听）|
| **错误态** | 列表加载失败 | Toast"加载失败"+ 重试按钮 | 点击重试不弹 loading 圈（直接重发请求）|

**播放页**：
| 状态 | 触发条件 | UI 表现 | 关键设计 |
|---|---|---|---|
| **正常** | 正在播放 | 全文文字稿 + 进度条 + 控制按钮 | 高亮当前播放段落（视觉锚点）|
| **加载** | 切换下一首 / 网络慢 | 整屏加载动画（脉冲圆圈）| 加载超过 3 秒 → 显示"卡住了？点击重试"|
| **空态** | 极少（用户主动进空列表的播放页）| "这篇已删除"+ 返回按钮 | 不让用户困在空态 |
| **错误态** | 音频加载失败 / 中途断流 | 顶部条"网络中断"+ 自动重连 3 次 | 3 次失败后弹"重新蒸馏此文章？"按钮 |

**加入成功页**：
| 状态 | 触发条件 | UI 表现 | 关键设计 |
|---|---|---|---|
| **正常（蒸馏中）** | 加入后立刻 | "30 秒后就绪"倒计时进度条 | 倒计时消失 = 蒸馏完成，自动跳转到播放器 |
| **正常（已完成）** | 加入时已就绪 | 直接显示"立即收听"按钮 + 自动跳转播放器 | "立即收听"按钮高亮 + 触觉反馈 |
| **正常（失败）** | 蒸馏失败 | "蒸馏失败"+ 三个按钮："换源重试"（主）/"查看原文"（次）/"反馈问题"（次）| "换源重试"自动重试 1 次（命中失败率最高的 50%）|
| **加载** | 网络抖动 | 整页骨架屏 | < 800ms 不显示 |

**标签库**：
| 状态 | 触发条件 | UI 表现 | 关键设计 |
|---|---|---|---|
| **正常** | 有 1+ 标签 | 标签云 + 数量统计 | 点标签 → 进入"该标签下的文章列表" |
| **加载** | 首次打开 | 标签云骨架屏 | < 500ms 不显示 |
| **空态** | 用户从未标过任何文章 | 大图标（🏷️）+ 文案"还没有任何标签"+ 次按钮"自定义标签" | 不引导"立即给文章打标签"——会破坏用户工作流 |
| **错误态** | 加载失败 | Toast + 重试 | 同主屏 |

**个人中心**：
| 状态 | 触发条件 | UI 表现 | 关键设计 |
|---|---|---|---|
| **正常** | 配额充足 | 完整信息（会员状态 + 配额 + 按钮）| 配额 < 10% 时变橙色提示 |
| **加载** | 首次打开 | 骨架屏 + 加载动画 | < 300ms 不显示 |
| **配额耗尽** | 已用 ≥ 配额 | 配额区块变红 + 主按钮变"升级专业版"+ 横幅"本月配额已用完"| 横幅置顶 + 不可关闭 |
| **错误态** | 加载失败 | Toast + 重试 | 不让用户看不到自己配额（安全感） |

#### 2.3.7 手势交互设计（v2.1 增补）

**5 个屏幕的交互手势**——以"减少按钮 + 增加手势"为原则（按钮占用空间，手势零成本）。

| 屏幕 | 手势 | 行为 | 设计意图 |
|---|---|---|---|
| **主屏** | 上滑列表 → 顶部露出"搜索" | 出现搜索栏（搜索标签 / 标题） | 用户找旧内容时不用进二级页 |
| | 下拉刷新 | 触发列表刷新 | 标准 iOS / Android 习惯 |
| | 长按列表卡片 | 弹出快捷菜单（标完成 / 删除 / 标星） | 减少进详情页的操作 |
| **播放页** | 左右滑动 → 上一段 / 下一段 | 段落跳转（非整首） | 用户听感是"段"，不是"首" |
| | 双击屏幕中间 → 播放 / 暂停 | 切换播放状态 | 比点击暂停按钮快 |
| | 长按屏幕中间 → 1.5× 速播放 | 临时加速（松手恢复） | 通勤场景的"快进跳过废话" |
| | 下滑 → 回到主屏 | 切换应用 | 锁屏时仍可控制（系统级） |
| | 双击 15 秒回放（锁屏时）| 跳到 15 秒前 | iOS 用户习惯（Podcast 借鉴） |
| **加入成功页** | 右滑 → 关闭 | 返回调用页 | 比点击"继续浏览"快 |
| **标签库** | 长按标签 → 编辑 / 删除 | 弹出操作菜单 | 用户管理标签 |
| | 左滑标签 → 删除（带 undo） | 快速删除 | 标准 iOS 习惯 |
| **个人中心** | 无特殊手势 | 全按钮 | 重要操作，明确可见 |

**手势发现性**：每个屏幕首次出现时显示**3 秒提示气泡**（"左滑切换上一段"），关闭后不再显示。

**无障碍考虑**：所有手势必须有**等效按钮**（iOS VoiceOver / Android TalkBack 用户不能用纯手势）。

- **2026-09-09 拍板**：状态矩阵 4 态全覆盖，避免"上线后才发现空态 / 错误态没设计"

### 2.4 UX 三大原则

#### 原则 1：懒打开（首屏 = 列表 + 自动播放）

- 用户**不应该**为听匣做"准备动作"
- 进入 App = 自动开始播放最新加入
- 零学习成本

#### 原则 2：零摩擦（加入 ≤ 3 秒）

- D9 路径 = **2 步**（点击"更多打开方式"→ 选听匣）
- 不要求用户注册（先用 device_id 临时存）
- 不要求用户先装 App（未装跳转商店 + 任务恢复）

#### 原则 3：不打扰（无通知轰炸）

- 蒸馏完成 = 静默通知（用户设置时可关）
- 不强推会员升级
- 不展示广告

### 2.5 L4 听感改写 5 条铁律（UX 标准）

> 这些是产品对 AI 输出的"质量验收标准"——开发必须实现，QA 必须测试。

1. **信息密度**：每分钟 200-260 字（实测通勤最佳节奏）
2. **数字处理**："32%" → "百分之三十二"；"2026 年" → 默认不念年份
3. **图表叙事**：每张图 1-3 句口语描述（不超过 3 句）
4. **段落口语化**：删"综上所述"、"值得注意的是"、"首先...其次..."
5. **错误率**：不读错字 / 不读破句

   ↓ 用户再次点击 → 重试机制
15:05 导出成功，浏览器下载 .zip
```

**听匣兜底**：异步导出 + 进度提示 + 失败重试

**关键指标**：D 类导出成功率 ≥ 95%

### 4.2 核心数据流（4 步流水线）

```
用户"丢链接" → content-service 创建 articles 行 + 扣配额
            ↓
            ↓ 入 distill_tasks 队列
            ↓
            ↓
ai-service Worker 拾取任务（4 步流水线）：
  Step 1: 抓取 (Fetch) ──────→ wechat-crawler / readability / pdfplumber
  Step 2: 蒸馏 (Distill) ────→ Qwen2.5-VL-72B (Step 1 摘要) + Claude 4 Sonnet (Step 2 改写)
  Step 3: 标签 (Tag) ────────→ Claude 4 Sonnet (Step 3 标签)
  Step 4: 合成 (Synthesize) ─→ 豆包 TTS
            ↓
            ↓
content-service 更新 articles.status = ready
            ↓
notification-service 通过 WebSocket 推送给 App
            ↓
            ↓
用户通勤路上听到 AI 改写的音频
```

**4 步的核心价值**：
- **不是"读稿 TTS"**——是 AI **重新写**通勤版
- **不是"通用大模型"**——4 个模型各司其职
- **不是"全量改写"**——只改关键信息密度

### 4.4 AI 蒸馏核心（4 步详解）

#### Step 1：多模态理解（Qwen2.5-VL-72B）

**为什么选 Qwen2.5-VL**：
- 国产合规（数据不出境）
- 中文图表理解强
- 价格 ¥0.6/篇，可控

**输入**：原文 + 图片 + 表格
**输出**：JSON 结构化摘要（200-300 字概要 + 3-7 个关键点 + 图表描述 + 实体识别）

#### Step 2：听感改写（Claude 4 Sonnet）

**为什么选 Claude 4 Sonnet**：
- 中文写作质量比 Qwen 更自然
- 听话感改写是"创意写作"，Claude 优势明显

**输入**：Step 1 的 JSON
**输出**：Markdown 听感稿

**核心 Prompt 骨架**（这是产品对开发交付的"质量标准"）：

```
你是"通勤听感改写"专家。

输入：已提取结构化摘要的文章（JSON）

任务：
1. 删除所有视觉元素描述（"如图所示"、"见右表"）
2. 把图表改写成 1-3 句口语化描述
3. 把数字改写成听感版本（"32%" → "百分之三十二"）
4. 删除书面连接词（"综上所述"、"值得注意的是"）
5. 控制信息密度：每分钟 200-260 字
6. 输出 Markdown 格式的"听感稿"

听感稿结构：
- 开头 1 句：核心观点
- 主体：3-5 个关键点（每点 100-200 字）
- 结尾 1 句：行动建议或思考
```

#### Step 3：标签提取（Claude 4 Sonnet）

**输入**：Step 2 听感稿（共享 context，省钱）
**输出**：3-5 个标签 + 置信度

**为什么不训练模型**：标签提取不需要微调；Claude 通用能力足够；改 prompt 即可

#### Step 4：TTS 合成（豆包语音 / CosyVoice）

**为什么豆包为主**：
- 中文音质自然
- 价格 ¥0.5/篇
- 国内合规

**CosyVoice 备**：豆包挂了 fallback

**文本预处理**（决定听感的关键步骤）：
- Markdown 标记去掉
- 数字处理（"¥29" → "二十九元"）
- 百分号 → "百分之"
- 长句切分（避免 TTS 断句错误）

#### 单篇成本表（核心 4 类文章）

| 文章类型 | Step 1 | Step 2 | Step 3 | Step 4 | **总成本** |
|---|---|---|---|---|---|
| 公众号图文（5 千字 + 5 图）| ¥0.6 | ¥0.27 | ¥0.06 | ¥0.5 | **¥1.43** |
| 公众号长文（2 万字 + 10 图）| ¥1.5 | ¥0.44 | ¥0.07 | ¥1.5 | **¥3.51** |
| 抖音视频精华（1 分钟）| ¥0.3 | ¥0.18 | ¥0.06 | ¥0.3 | **¥0.84** |
| 抖音视频全文（30 分钟）| ¥0.9 | ¥0.36 | ¥0.06 | ¥0.5 | **¥1.82** |

**PMF 拐点成本测算**：10000 用户 × 8% 付费率 × 50 篇 × ¥1.43 = **¥57,200/月**（含免费用户）

### 4.5 核心 API（6 个关键端点）

> 完整 API 清单（19 个端点）见技术方案 v1.1 §3——本节只列最关键的 6 个。

#### 用户端最常用 3 个

1. **`POST /api/v1/articles/add`** — 加入文章
2. **`GET /api/v1/articles/pending`** — 待听列表
3. **`GET /api/v1/user`** — 当前用户信息

#### 系统最关键 3 个

4. **`POST /api/v1/callback/d9-add-article`** — D9 入口（生死线）
5. **`POST /api/v1/callback/wechat-pay`** — 支付回调
6. **`WS /ws/articles/{id}/progress`** — 蒸馏进度推送

**API 设计 4 大原则**：
- **统一响应格式**：`{ code, message, data, trace_id, server_ts }`
- **错误码分组**：1000 鉴权 / 2000 文章 / 3000 配额 / 4000 订阅 / 5000 系统 / 9xxx 服务
- **幂等性**：`client_request_id` + 数据库唯一索引兜底
- **频率限制**：用户级 + IP 级双重

#### 5.2.1 v2 历史决策（D1-D9 · 9 个）展开论证（v2.1 新增 · Hornet 2026-09-09 拍板）

**为什么补这节**：53 个决策只有一行标题，评审委员会看完不知道"为什么这么选"——这是 v2 §5 最大的"空洞"。

**D1 · 产品名"听匣"**
- 备选：「随口听 / 朗读器 / 阅读电台 / 听匣 / 通勤听 / 速读 FM」
- 选「听匣」理由：①"匣"是容器意象（把内容装进去带走）② "听"是核心动作 ③ 二字顺口，5 个备选唯一通过"不拗口"测试
- 否决「朗读器」理由：太工具化（像 TTS 工具），缺产品人格
- 否决「通勤听」理由：场景太窄（不只通勤），"听匣"覆盖更多场景
- 可反转点：二期前可改，但所有营销物料、App 商店、ICP 备案都要重做

**D2 · 副标题"通勤路上的 30 分钟电台"**
- 备选：「30 秒把文章变成音频」/「通勤路上的 30 分钟电台」/「让每篇文章都能听」/「你的私人音频日报」
- 选「通勤路上的 30 分钟电台」理由：①"30 分钟"锚定时长（实际平均 22 分钟，加开头结尾 = 30 分钟）②"电台"暗示内容流，不是工具 ④ 让用户立刻 get 到"听匣 vs 朗读器"的差异
- 否决"30 秒变音频"理由：太强调速度（实际 30 秒只完成蒸馏，**不是音频长度**），用户期待错位
- 可反转点：副标题常改，但 App Store 描述改了要重审

**D3 · C 端三件套（App + D9 + 服务号）**
- 备选：「只做 App」/「App + D9」/「App + D9 + 服务号」/「只做服务号（公众号形态）」
- 选三件套理由：① App 是核心载体（后台播放 + 锁屏控制）② D9 是**唯一无 App 也能用的入口**（最广触达）③ 服务号是**微信生态的桥**（公众号文章天然来源）
- 否决"只做 App"理由：装了 App 才用 → 用户基数小；D9 让"看公众号 → 听摘要"1 步直达
- 否决"只做服务号"理由：服务号没法后台播放 + 锁屏控制，体验差
- 可反转点：三件套中服务号可推迟到二期（最低优先级）

**D4 · 不做小程序 PWA**
- 备选：「做 PWA（小程序 + 网页版）」/「不做 PWA」
- 不做理由：① PWA 后台播放体验差（iOS Safari 后台限制 30 秒）② 用户主场景是通勤（手机锁屏），PWA 锁屏控制弱 ③ PWA 缓存大（音频文件），iOS 经常清缓存
- 风险：安卓 PWA 后台播放比 iOS 好，但 iOS 用户占 60%+，不做 PWA 是为体验放弃覆盖
- 可反转点：iOS 解除后台限制后可重启 PWA（短期不会发生）

**D5 · 抖音视频核心（ASR + 精华摘要）**
- 备选：「不支持视频」/「支持视频但只 ASR 不挑精华」/「支持视频 + 智能摘要精华」

**D6 · 主题标签（用户长期资产）**

#### 5.7.4 推荐算法 v1 详细设计（一期 CP6 完成后启动）

**触发**：一期 1000+ 用户埋点数据 + feedback 表 ≥ 5000 条

**v1 方案（无 ML，3 周内上线）**：
- **基于主题标签相似度**：用户听过"AI"标签的文章 → 推荐同标签其他用户的"AI"高分文章
- **基于共同用户**：用户 A 喜欢的文章，其他 ≥ 5 个用户也喜欢 → 推荐给 A
- **基于时间衰减**：最近 30 天用户喜欢的内容权重 × 1.5（"近期偏好"）

**v2 方案（需要 ML，6 周上线）**：
- 协同过滤（user-based / item-based）
- Embedding 向量相似度（用 Qwen2.5-7B 蒸馏用户行为序列）
- LLM 总结"用户本周兴趣点" → 注入到 Step 2 prompt 作为上下文

**核心指标**：
- **推荐点击率** ≥ 30%（点击 / 展示）
- **推荐完成率** ≥ 50%（听完 / 点击）
- **推荐带来的留存提升** ≥ 5%（对比无推荐组）

#### 5.7.5 决策反转触发器

**任何二期方向被推迟后**：
- **定期评估**（每季度）：用户量 / 反馈 / 战略价值是否变化
- **触发条件**：用户数 > 10000 → 重新评估"多账号体系"
- **触发条件**：D 类付费 > 50 → 重新评估"AI 摘要导出 PDF"
