## 3. 分批详细设计

### B1 · G1 四维评分提交（P0，解锁 Android 评分 UI + 打破 D3 数据空转）

```
POST /api/v1/distill/{task_id}/evaluation          # Authorization: Bearer <user JWT>
req:  { hook_score?, section_score?, outro_score?, rhythm_score?,   # 各 1-5
        overall_score,                                              # 1-5 必填
        comment?, skip_reason? }
resp: { id, task_id, overall_score, in_few_shot_pool, pattern_updated }
```

实现要点：
1. 归属校验 = `distill_status` 同款（查 Article.user_id）；task_id 即 `dst_xxx`。
2. 写 `DistillationEvaluation(auto_flag=false)` —— user_id 取 JWT sub。
3. **同请求内联动**（fire-and-forget 包 try/except，失败只 log、响应里标记 false，不吞评分写入）：
   - `overall_score >= 4` → `add_high_score_to_pool(db, evaluation)`（few-shot 入池门槛与 hook 一致）
   - → `update_user_listening_pattern(db, user_id, evaluation)`（画像更新，冷启动 <5 篇自动 NULL 保护已有）
4. 校验：4 维各字段可 null 但给了必须 1-5；overall 必填 1-5；skip_reason ≤32 列宽。越界业务 400。
5. 与 `/rate`（feedback 表）的关系：**双轨并存不合并**——rate 是文章粒度（content），evaluation 是蒸馏任务粒度（ai），驱动链路不同。文档已各自标注。

G5 顺手修：`config.py` 显式注册 `/api/v1/distill/{task_id}/variants`（GET）、`.../warm`（POST）、`.../evaluation`（POST）三条，消除对 fallback 猜表的路径依赖。

### B2 · admin 只读看板（P1，纯包装零风险）

新文件 `ai-service/admin_router.py`，统一 `Depends(require_admin_or_operator)`：

| 端点 | 实现 | 响应 |
|---|---|---|
| `GET /admin/few-shot-pool/health` | `PoolHealthMonitor().compute_health(db)` 直调 | PoolHealthReport（schema 已存在，含 warning/health_score） |
| `GET /admin/few-shot-pool?kind=&min_score=&active=true&limit=&offset=` | select 查表 | `{total, items}` |
| `GET /admin/evaluations?auto_flag=&min_score=&task_id=&limit=&offset=` | select 查表 | `{total, items}` |
| `GET /admin/audio-variants/stats` | `GROUP BY bitrate` 计数 + 覆盖率（有变体的 done 文章数 / done 总数） | `{by_bitrate, coverage_ratio}` |
| `GET /admin/consents?limit=&offset=` | select 查表（user_id/两开关/版本，**GDPR 注意不回显 comment 类自由文本**） | `{total, items}` |

写审计日志（对齐 admin_router 惯例：导出/查询类现有实现不写审计，**只读端点维持不写**）。ROUTES 注册 5 条（admin 段不走 fallback）。

### B3 · admin 写操作（P1-P2）+ D2 接线

**A1 tier-config（含 D2 修复，本批次核心）**：
1. `common/system_config.py` 加 `KEY_TIER = "tier"`（一行）。
2. `tier_router.py` 加 `async resolve_tier_map() -> dict`：DB（system_config）> 代码默认 TIER_MODEL_MAP，Redis 缓存复用 system_config 现成机制。`get_model_for_tier` 改为读 resolve 结果。
3. **D2 接线**：`pipeline.py` Step1/Step2 调 LLM 处，把 `ctx.target_tier` 传进 `get_llm_client(model_name=resolve_tier_map()[tier][provider])`——factory 本就支持 model 覆盖，只差这 2 个调用点。这等于把 CP3.6.2 遗留的「tier 路由不生效」补完。
4. 端点：`GET /admin/tier-config`（返回生效映射 + source=db/env）/ `PUT`（校验 tier ∈ {simple, full}、provider 白名单，写 system_config；蒸馏任务启动前已有 `llm_reload()`，tier map 在 resolve 时读缓存，无需重启）。
5. ⚠️ provider 键当前只有 openai/qwen_vl/claude 三组——与 llm/factory 实际支持的 provider 对齐后再接线（deepseek/glm 未实现 client，配了也不生效，端点响应里给 warning 字段）。

**A3 annotate（评测员标注）**：
```
POST /admin/evaluations/{id}/annotate
req: { hook_score?, ..., overall_score }    # 评测员 4 维 + 总评
```
- 写**新行**（auto_flag=false, user_id=NULL 表示评测员来源；evaluator 归属走 admin JWT sub 存 comment 前缀或加列——**决策点 §5.2**）。
- 校准统计：`GET /admin/evaluations/agreement` 直调 `compute_inter_evaluator_agreement`（纯函数）。

**A6 池运营**：`POST /admin/few-shot-pool/cleanup`（调 run_full_cleanup，返回删除/软删计数）、`GET .../audit-sample?size=20`（select_for_audit）、`POST .../audit-result`（record_audit_result，回写 score_avg）。写操作带 `reason` 落 admin_operation_logs。

**A8 盲测**：`POST /admin/tts/blind-test`（setup：取 N 篇高分文本 × 各 provider 合成 + 随机洗牌，存 task 记录）+ `GET /admin/tts/blind-test/{id}/results`（compute_blind_score 中位数聚合）。**依赖真 TTS 配额，默认 mock provider 下仅打通链路**。

### B4 · A/B 数据底座（P1，修 D1）+ ab-report

1. **Alembic 0029**：`distilled_articles` 加 `ab_group VARCHAR(16) NULL`、`is_personalized BOOLEAN NULL`（nullable、不动旧数据——旧行 NULL = 「未实验期」，报表按 NULL 过滤）。
2. `FewShotSelectorHook` 决策后把 `ab_group`/`is_personalized` 写入 ctx（已有字段），**pipeline `_write_final_to_db` 补两列落库**（1 处改动）。
3. `GET /admin/ab-report?from=&to=`：按 `ab_group` 分组聚合四指标（方案 §2.7-D 口径）——复听率（feedback type=listen_complete 去重/曝光）、完听率（progress.position_sec/duration_sec ≥ 0.9）、评分均值（evaluations.overall）、跳过率（articles.skip）。
4. ⚠️ 诚实标注：**0029 上线前的历史蒸馏数据无分组，A/B 结论只能从部署日重新计 2 周**。越早上线越好，建议与 B3 同迭代。

## 4. 横切约束（每个端点适用的验收红线）

1. **ROUTES**：新增 admin 路由必须同步注册 `api-gateway/config.py`（admin 段无 fallback，漏一条 = 前端 404，历史根因）。B1 用户端点显式注册消 G5。
2. **鉴权口径**：用户端点 `require_user` + 归属校验；admin 端点 `require_admin_or_operator`；写操作（B3 全部）同事务写 `admin_operation_logs`。
3. **密钥/隐私**：tier-config 不含 key 字段；consents 端点不回显自由文本；evaluations 的 comment 仅 admin 可见（本来就是 admin 端点）。
4. **响应信封**：列表 `{total, items}` + limit/offset；错误走 BizException（业务 400 优先于 422）。
5. **测试**：沿用 SQLite 内存库套路（stub 表绕过 JSONB，CP3.7.3/7.3.0 已趟平）+ FastAPI TestClient；每端点至少 成功/401/403(或归属越权)/参数越界 4 用例。跑测试带 `STASHBOX_ALLOW_DEV_JWT=1` + `--basetemp`。
6. **commit 规范**：`git -c user.name=Coder -c user.email=coder@yuanyong-ai.com commit`；subject 小写英文（commitlint subject-case 钩子，中文 subject 会被拦——上轮已踩）。每批一个 commit。
