## 0. 全局约定

### 0.1 Base URL 与鉴权

| 环境 | Base URL |
|---|---|
| dev | `http://localhost:8100`（Vite 5173 经 proxy 或直连，CORS 默认 `*`） |
| 生产 | 待定（一律经 api-gateway） |

**鉴权两级**（JWT payload 的 `tier` 字段判定）：
| 依赖 | 允许角色 | 应用范围 |
|---|---|---|
| `require_admin_or_operator` | tier ∈ {admin, operator} | 下文**全部** admin 端点 |
| `require_admin` | 仅 admin | 暂未使用（预留高危操作） |

登录：`POST /api/v1/admin/auth/login`（user-service，账号密码换 JWT；dev 种子账号见 alembic 0015 迁移，凭据不写入本文档）。403 响应：`{"detail":"admin role required, current tier: free"}`。

### 0.2 错误信封

与 Android 文档 §0.2 相同（`{code, message, data}`；400/401/403/404/422/429 语义一致），不再重复。

### 0.3 路由可达性（重要）

admin 路径**不在网关 fallback 猜测表内**（fallback 只认 articles/tags/callback/user/subscription/distill 前缀），**每条 admin 路由都必须在 `api-gateway/config.py` ROUTES 显式注册**，否则 8100 返回 `404 {"detail":"no downstream route"}`。

截至 `ae6c594`，ROUTES 已注册 **40 条** admin 路由：原 24 条（articles/audit-log/stats/export/llm/tts/tags/auth/users 系）+ B2 5 条 + B4 ab-report 1 条 + B3 10 条。**听感运营新端点（§2.2）全部已注册 ✅，可直接联调。**

⚠️ 网关按**精确路径**注册，无参数前缀通配：新增子路径（如 `/evaluations/{id}/annotate`）必须逐条补 ROUTES——历史联调 404 的头号根因。

### 0.4 审计留痕约定

写操作（force-retry / invalidate / 删文章 / 删标签 / config PUT / CSV 导出 / **§2.2 全部 B2-B4 写端点**）由 api-gateway `AuditMiddleware` 自动落 `admin_operation_logs`（fire-and-forget + 敏感字段脱敏），admin-web 无需额外上报；`GET /api/v1/admin/audit-log` 可查。删除标签/文章类接口要求 `reason`（≥5 字符）。

#### A4 · A/B 实验报表（B4）

`GET /api/v1/admin/ab-report?date_from=2026-10-01T00:00:00&date_to=2026-10-15T00:00:00`（可都不传 = 全量）→ 200
```json
{
  "groups": [
    { "group": "personalized", "tasks": 41,
      "avg_overall_score": 4.2, "eval_count": 30,
      "play_count": 55, "complete_count": 40, "completion_rate": 0.7273,
      "rewatch_pairs": 12, "play_pairs": 41, "rewatch_rate": 0.2927,
      "skip_count": 3, "skip_rate": 0.0732 },
    { "group": "general", "...": "同结构" },
    { "group": "pre_experiment", "...": "同结构（0029 上线前历史数据，ab_group=NULL）" }
  ],
  "caveats": [
    "0029 迁移上线前的历史蒸馏数据 ab_group=NULL，归入 pre_experiment 组，不可用于 A/B 结论",
    "A/B 结论需从 ab_group 落库部署日起重新计 2 周（方案 §2.7-D 周期）"
  ]
}
```
- 分组口径（intention-to-treat）：`user_id % 100 < 30` → personalized，其余 general；与是否实际命中个性化无关（冷启动也入组）。
- 四指标语义：复听率 = 同一 (user,article) ≥2 次 `audio_play_start` 的 pair / 有播放的 pair；完听率 = `audio_complete`/`audio_play_start` 事件比；评分均值 = `distillation_evaluations.overall_score`；跳过率 = `articles.skip=true` / 组内 done 任务数。
- 无数据的指标为 `null`（分母为 0 时不硬算 0）。UI 建议：组数 <2（pre_experiment 不算）时显示「数据积累中」。
- ⚠️ **结论有效性硬约束**：报表口径从 0029 部署日起算——admin-web 文案务必带上 caveats。

## 2.5 音色库（CP-TTS-VOICE，2026-09-30 新增）

IndexTTS 是零样本克隆，音色 = **(参考音频, 参考文本) 对**，不是 provider 那种填个
voice 名字就行的字符串。这决定了下面所有字段的形状，以及为什么 `ref_text` 是必填。

⚠️ 迁移 `0033` **刻意没 seed 默认音色**：迁移里读 env 会把本机绝对路径
（`/Users/hornet/work/.../tingting_ref.wav`）固化进库，换台机器就是死路径。
首次使用请调 `import-from-config` 完成冷启动（见下）。

### 2.5.1 CRUD

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/admin/tts/voices` | 列表（**含已下架**） |
| POST | `/api/v1/admin/tts/voices` | 新建 |
| PUT | `/api/v1/admin/tts/voices/{voice_id}` | 更新（不传的字段不动） |
| DELETE | `/api/v1/admin/tts/voices/{voice_id}` | 软删 |
| POST | `/api/v1/admin/tts/voices/{voice_id}/preview` | 试听（真合成） |
| POST | `/api/v1/admin/tts/voices/import-from-config` | 从当前 TTS 配置导入（幂等） |

创建/更新请求体：

```json
{
  "slug": "tingting",
  "display_name": "婷婷",
  "ref_audio_url": "/Users/hornet/work/stashbox/backend/data/voices/tingting_ref.wav",
  "ref_audio_b64": null,
  "ref_text": "今天天气不错，我们一起来看看这条新闻讲了什么内容。",
  "description": "温和女声",
  "is_default": true,
  "is_active": true,
  "sort_order": 0
}
```

- `ref_audio_url` 与 `ref_audio_b64` **二选一**
- `ref_audio_url` 接受**本机绝对路径**（dev）或 **http(s) URL**（S3/OSS）——
  `IndexTTSClient._load_ref_audio_b64` 两种都认
- `ref_audio_b64` 是纯 base64（不带 `data:` 前缀也行，后端会剥）。
  **刻意用 base64 而不是 multipart**：admin-web 的 axios 实例硬编码了
  `Content-Type: application/json`（`src/api/client.ts:43-45`），FormData 要逐请求
  覆盖 header，本项目无先例。代价是体积涨 33%，参考音频通常 3~15 秒可接受
- 上传校验：必须是 wav（RIFF 头）、≥1KB、≤10MB
- `ref_text` **必填且必须与音频内容一致** —— 克隆出的音色会念错，这是本模块
  最容易配错、也最难在界面上看出来的点

### 2.5.2 三个约束（都是实测踩出来的）

1. **`is_default` 至多一条**（DB 部分唯一索引 `idx_tts_voices_single_default`）。
   管理员不设任何默认是允许的 —— 解析链会退到全局 TTS 配置，不会挂
2. **软删会把引用它的用户偏好置空**（`user_tts_preferences.voice_id` → NULL），
   用户自动回落默认音色，而不是下次打开 App 看到一个指向已删音色的选中态
3. **`slug` 创建后不可改**（`is_default` / `is_active` 可改）。App 侧按 slug 缓存

### 2.5.3 试听是真合成

`preview` 会拿该音色的 `ref_audio` 真的调一次 oMLX 合成（约 10~20 秒），返回
wav 的可下载 URL。音色库里最容易翻车的两件事 —— 参考音频和参考文本对不上、
音频根本不是有效 wav —— 只有真合成一次才会暴露。返回的 URL 直接 `window.open`。

### 2.5.4 冷启动：import-from-config

```json
// 响应
{ "voice": { "id": "ttsv_...", "slug": "default", "display_name": "默认音色", ... },
  "created": true }
```

把当前全局 TTS 配置里的 `indextts_ref_audio` 收编成音色库第一条。**幂等**：
已收编过返回 `created: false` 且不造重复行（按 `ref_audio_url` 比对）。
