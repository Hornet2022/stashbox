## 0. 全局约定

### 0.1 Base URL 与鉴权

| 环境 | Base URL |
|---|---|
| dev | `http://localhost:8100`（Vite 5173 经 proxy 或直连，CORS 默认 `*`） |
| 生产 | 待定（一律经 api-gateway） |

**鉴权两级**（JWT payload 的 `tier` 字段判定）：
| 依赖 | 允许角色 | 应用范围 |
|---|---|---|
| `require_admin_or_operator` | tier ∈ {admin, operator} | 下文**全部** admin 端点 |
| `require_admin` | 仅 admin | 暂未使用（预留高危操作） |

登录：`POST /api/v1/admin/auth/login`（user-service，账号密码换 JWT；dev 种子账号见 alembic 0015 迁移，凭据不写入本文档）。403 响应：`{"detail":"admin role required, current tier: free"}`。

### 0.2 错误信封

与 Android 文档 §0.2 相同（`{code, message, data}`；400/401/403/404/422/429 语义一致），不再重复。

### 0.3 路由可达性（重要）

admin 路径**不在网关 fallback 猜测表内**（fallback 只认 articles/tags/callback/user/subscription/distill 前缀），**每条 admin 路由都必须在 `api-gateway/config.py` ROUTES 显式注册**，否则 8100 返回 `404 {"detail":"no downstream route"}`。

当前 ROUTES 已注册 ✅ 的 admin 端点：articles 列表/详情/force-retry/删除、audio invalidate、audit-log、stats、distill-p95、llm/tts config+test、export ×5、tags 列表/删除、auth/login、users、quota-adjust。
**缺口 A6（TIER 模型映射）等拟定端点上线时需同步补 ROUTES 注册**——这是历史上 admin-web 联调最常见的 404 根因。

### 0.4 审计留痕约定

写操作（force-retry / invalidate / 删文章 / 删标签 / config PUT / CSV 导出）后端自动落 `admin_operation_logs`，admin-web 无需额外上报；`GET /api/v1/admin/audit-log` 可查。删除标签/文章类接口要求 `reason`（≥5 字符）。

## 1. 现有端点全量清单（可立即对接）

### 1.1 Dashboard / 统计

**`GET /api/v1/admin/stats`**（内存缓存 30s）
```json
{
  "total_users": 120, "total_articles": 3400,
  "pending": 12, "listened": 2100,
  "revenue": 0,                  // orders 表缺失时恒 0
  "active_audio_files": 3300,    // distilled done 且有 audio_url
  "failed_distillations_24h": 3
}
```

**`GET /api/v1/admin/distill-p95`**（从 ai-service + worker 的 Prometheus 解析，缓存 30s）
```json
{
  "cached": false,
  "by_step": {
    "step1_structuring": { "p50": 3.2, "p95": 8.1, "p99": 12.0 },
    "step2_rewriting":   { "p50": 2.0, "p95": 5.5, "p99": 7.8 },
    "step3_ttsing":      { "p50": 9.0, "p95": 21.0, "p99": 30.0 },
    "step4_concatenating": { "p50": 0.4, "p95": 1.1, "p99": 2.0 }
  },
  "overall": { "p50": 3.6, "p95": 8.9, "p99": 13.0 }
}
```
- 抓不到 metrics 时返回 `{"by_step":{}, "overall":{...null}, "error":"..."}`（200，非 5xx）。

### 1.2 文章运营

| 端点 | 说明 |
|---|---|
| `GET /api/v1/admin/articles?limit=50&offset=0&status=&tag=` | 全量列表（不按 user 过滤）；`status` ∈ pending/distilling/ready/failed；`tag` 传 slug |
| `GET /api/v1/admin/articles/{article_id}` | 详情：`{article:{...error, retry_count, raw_content_summary}, distilled:{id,status,audio_url,duration_sec,tags,quality_score,script_text[:300]}}` |
| `POST /api/v1/admin/articles/{article_id}/force-retry` | 失败文章强制重蒸（body: `AdminActionRequest {reason}`） |
| `DELETE /api/v1/admin/articles/{article_id}` | 删文章（reason 必填，级联清理音频文件走 storage.delete） |
| `POST /api/v1/admin/audio/{audio_id}/invalidate` | 音频作废（bad case 处置入口，reason 必填） |

### 1.3 模型配置（热生效，无需重启）

**LLM**：`GET/PUT /api/v1/admin/llm/config` · `GET /api/v1/admin/llm/test`（真调一次 chat 验证）
```json
// PUT 请求（字段语义：不传=不动；显式 null/""=清空回 env）
{ "provider": "deepseek", "model": "deepseek-chat", "api_key": "***", "base_url": null }
// GET 响应（api_key 永不明文回显）
{ "provider": "deepseek", "model": "deepseek-chat", "base_url": null,
  "api_key_set": true, "api_key_last4": "3f2a", "source": "db", "updated_at": "..." }
```
- `provider` 白名单校验，非法值 400（deepseek/glm 的 client 未实现时回落 mock，报文中提示）。

**TTS**：`GET/PUT /api/v1/admin/tts/config` · `GET /api/v1/admin/tts/test`
- PUT 字段：`provider`(edge|openai|doubao|local|indextts|mock) + 各家参数（`edge_voice` / `openai_api_key,openai_base_url,openai_model,openai_voice` / `doubao_api_key,doubao_token,doubao_app_id,doubao_voice,doubao_resource_id` / `local_voice,ffmpeg_bin` / `indextts_base_url,indextts_model,indextts_ref_audio,indextts_ref_text`）。
- test 端点可用 `ENABLE_TTS_TEST_ENDPOINT=0` 关闭（关闭后 404）。

### 1.4 用户与配额

| 端点 | 说明 |
|---|---|
| `POST /api/v1/admin/auth/login` | 账号密码登录（user-service） |
| `GET /api/v1/admin/users` | 用户列表（AdminUserListResponse） |
| `POST /api/v1/admin/users/{user_id}/quota-adjust` | 配额调整（返回 UserQuotaResponse） |

### 1.5 标签运营

- `GET /api/v1/admin/tags` —— 含**数字 id** + `is_system` + `subscriber_count`（用户端 GET /tags 只有 slug，删除按钮必须用 admin 版）。
- `DELETE /api/v1/admin/tags/{tag_id}` —— `is_system=true` 拒绝（403）；reason ≥5 字符；级联由 DB 处理。

### 1.6 审计与导出

- `GET /api/v1/admin/audit-log?page=1&size=20&actor_id=&action_type=&from=&to=`（size 上限 100；from/to 为 ISO 时间串，解析失败静默忽略）→ `{total, items:[{id, actor_id, action_type, target_type, target_id, payload, created_at}]}`，按 created_at DESC
- CSV 导出（`StreamingResponse`，UTF-8 BOM，Excel 直开不乱码；每次导出写审计日志）：
  - `GET /api/v1/admin/export/users.csv`
  - `GET /api/v1/admin/export/articles.csv`（含 tags 竖线拼接、quality_score、listened_at）
  - `GET /api/v1/admin/export/feedback.csv`（v1 feedback 表：type=rate/skip/listen_complete…）
  - `GET /api/v1/admin/export/audit-log.csv`
  - `GET /api/v1/admin/export/subscriptions.csv`（表缺失时降级 header-only 合法 CSV）

## 2. 听感产品化新增能力 —— 后端状态与 admin-web 对接规划

> 本轮 CP 的工程实现落在 **ai-service 服务层 + Arq worker hook 链路**（蒸馏时自动运行），**尚未暴露 admin HTTP 端点**。下表说明每项能力的现状与建议对接方式。

### 2.1 已自动生效（admin-web 无需操作，可观测）

| 能力 | 来源 CP | 生效方式 | admin 观测入口现状 |
|---|---|---|---|
| 分层模型路由（simple/full tier） | 3.7.2 | 蒸馏 pipeline pre-hook 自动 | ❌ TIER_MODEL_MAP 无查询/热改端点（缺口 A1） |
| 低分自动重蒸（score≤2 且日限 3 次） | 3.7.3 | post-distill hook，env `AUTO_RETRY_ENABLED` | 间接：文章 retry_count / audit-log |
| few-shot 池自动入选（score≥4） | 3.7.3 | post-distill hook | ❌ 无池子查看端点（缺口 A2） |
| 个性化改写（A/B 30% + tier + 画像） | 5.6.0 | pre-hook 自动路由 | ❌ 无 A/B 报表端点（缺口 A4） |
| 多码率变体按需生成 | 7.3.0 | 用户请求驱动（Android §3） | ❌ 变体覆盖率无统计端点（缺口 A5） |
| 蒸馏质量自评 4 维入库 | 3.7.1/3.8.0 | `distillation_evaluations`（auto_flag=true 行为 LLM 自评） | ❌ 无查询端点（缺口 A3） |

### 2.2 运营功能缺口清单（需补后端端点，按优先级）

> 📐 **补齐方案已出**：《补齐方案_接口端点缺口_v1.md》（B1-B4 批次划分、端点契约、决策点）。其中走查发现 3 个比缺端点更根本的隐藏缺陷：D1 A/B 分组不落库（A4 的阻塞根因）、D2 TIER_MODEL_MAP 无调用方（A1 需先接线）、D3 evaluator 仍 mock（A3 评测标注是破局点）。

| # | 拟定端点 | 支撑的运营动作 | 后端已有实现 | 优先级 |
|---|---|---|---|---|
| A1 | `GET/PUT /api/v1/admin/tier-config` | 蒸馏模型映射热改（§2.8 风险表「LLM 涨价」应对） | `tier_router.TIER_MODEL_MAP`（dict，未接 system_config） | 🔴 P1 |
| A2 | `GET /api/v1/admin/few-shot-pool/health` + `GET /few-shot-pool?kind=&score=&limit=` | 池子健康度看板（高/中/低分布、过期率、health_score 0-100、warning 标签） | `pool_health.PoolHealthMonitor` ✅ 可直接包一层 | 🔴 P1（CP5.7.0 验收要求） |
| A3 | `GET /api/v1/admin/evaluations?score=&flag=&limit=` + `POST /evaluations/{id}/annotate` | 评测员打分（校准 baseline 3-5 人）、坏案例标注（1 星 + 评论 → 24h 响应流程） | `evaluator.collect_evaluator_calibration` ✅；表 `distillation_evaluations` 已建 | 🔴 P1（CP3.8.0 评测组要开工） |
| A4 | `GET /api/v1/admin/ab-report?from=&to=` | 个性化 vs 通用组的复听率/完听率/评分均值/退订率对比（A/B 2 周复盘） | 数据在 feedback + listening_status，聚合 SQL 未写 | 🟠 P2 |
| A5 | `GET /api/v1/admin/audio-variants/stats` | 多码率采用率（哪档被播、预热命中率）——CP7.4 预加载策略调优输入 | 表 `article_audio_variants` 已建 | 🟡 P3 |
| A6 | `POST /api/v1/admin/few-shot-pool/cleanup` / `POST /.../audit-sample` / `POST /audit-result` | 手动触发池子清理（stale/低质/去重）+ 抽取审计样本 + 录审计结果 | `pool_cleanup.PoolCleanupService` + `pool_audit.PoolAuditService` ✅ | 🟠 P2（也可先走 Arq 定时任务 + 本表只读） |
| A7 | `GET /api/v1/admin/consents?limit=` | GDPR 同意记录抽查（合规审计） | 表 `user_consents` 已建（0028 迁移） | 🟡 P3 |
| A8 | `POST /api/v1/admin/tts/blind-test` + `GET /.../blind-test/results` | TTS 音色盲测开测与结果（CP3.8.0 交付物之一） | `tts_blind_test.setup_blind_test/compute_blind_score` ✅ | 🟡 P3 |

**每项落地时的硬要求**（历史踩坑）：
1. **同步补 `api-gateway/config.py` ROUTES 注册**（§0.3）。
2. 依赖注入统一 `require_admin_or_operator` + `Depends(get_db)`；写操作同事务写 `admin_operation_logs`。
3. 响应里的密钥类字段一律掩码（对齐 `_masked_llm_config` 的 `api_key_set/api_key_last4` 模式）。
4. 响应信封统一 `{total, items}`；分页对齐现状二选一（列表类 limit/offset 如 admin/articles；审计类 page/size 如 audit-log），新端点建议 limit/offset 并在 ROUTES 注释标注。

## 3. 端到端联调冒烟（curl）

```bash
GW=http://localhost:8100
# 1. admin 登录
TOKEN=$(curl -s -X POST $GW/api/v1/admin/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"admin@stashbox.dev","password":"***"}' | jq -r .access_token)
AUTH="Authorization: Bearer $TOKEN"

# 2. Dashboard 数据
curl -s "$GW/api/v1/admin/stats" -H "$AUTH" | jq
curl -s "$GW/api/v1/admin/distill-p95" -H "$AUTH" | jq

# 3. 文章运营（列表 → 详情 → bad case 作废）
AID=$(curl -s "$GW/api/v1/admin/articles?status=failed&limit=1" -H "$AUTH" | jq -r .items[0].id)
curl -s "$GW/api/v1/admin/articles/$AID" -H "$AUTH" | jq
curl -s -X POST "$GW/api/v1/admin/articles/$AID/force-retry" -H "$AUTH" \
  -H 'Content-Type: application/json' -d '{"reason":"LLM 超时重试"}' | jq

# 4. TTS 配置热改 + 验证
curl -s -X PUT "$GW/api/v1/admin/tts/config" -H "$AUTH" \
  -H 'Content-Type: application/json' -d '{"provider":"indextts","indextts_base_url":"http://127.0.0.1:8008"}' | jq
curl -s "$GW/api/v1/admin/tts/test" -H "$AUTH" | jq

# 5. 审计回查（force-retry 应留痕）
curl -s "$GW/api/v1/admin/audit-log?limit=5" -H "$AUTH" | jq '.items[] | {action_type, target_id, created_at}'
```
