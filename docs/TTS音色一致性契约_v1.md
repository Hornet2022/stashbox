## 0. 一句话

**「一篇音频听出好几种音色」不是上游换了人，而是「段数太多 + 误判触发的额外切分 + 接缝重叠太长」三件事叠在一起。**

上游的说话人身份是**稳定的**（金标准 ECAPA 实测：克隆段与参考音余弦 0.75~0.80，
换人只有 0.29~0.35 —— 分得很开）。真正让人听出「好几种音色」的是**接缝**，
而接缝的数量被两件事放大：**块长太小** + **截断阈值误判引发的二分自愈**。

### 0.1 2026-11-25 修订后的一句话（含当晚根治，见 §2.5）

**「换人感」的根因分两层。表层是我们自己做的两件事；深层是零样本克隆的结构性事实：**

1. **逐块差异化移调**（音域对齐）——它要消除的「自然音域差」在身份层**无损**
   （1.38 半音 ⇒ 余弦 0.972~0.985），而它自己的变调**把余弦打到 0.867~0.940**
   （Δ **-0.105**）⇒ **治法比病更伤** ⇒ **默认关闭**。
2. **块长偏小** ⇒ 接缝多 ⇒ 每篇 1~3 次独立采样，每次采样都是一次「换人」的机会。
3. **深层（当晚证实，§2.5.1）**：**零样本克隆每个请求都重新采样一个说话人**——
   同一参考音频、同一文本，两次渲染身份也不同；块间 ~12% 概率采到不同人 ⇒ 接缝换人。
   这是克隆机制的固有属性，**调参/加长块/关对齐都只能降概率，不能根除**。
   （早先「上游从来没换过人」的说法基于恰好同人的样本，过强，已被存量核验证伪。）

⇒ **根治（用户拍板：固化音色、存量不动）**：改用**上游预设音色**（固定说话人，
`uncle_fu` 实测即婷婷本尊 0.8849）——预设不逐请求采样，跨块/跨请求身份稳定（§2.5.2）。
克隆机制保留给其它音色；存量 22 确证换人 + 2 回归**不再重生成**。


## 1. 证据（全部实测，2026-10-25）

### 1.1 上游能力：60s 墙钟是**端点**的，不是模型的

| 探测 | 结果 |
|---|---|
| 单次 250 字 | 200，墙钟 **12.1s** |
| 单次 800 字 | 200，墙钟 **31.8s** |
| 单次 1500 字 | 200，墙钟 **58.8s** |
| `stream: true` | **400**：「同步 /v1/audio/speech 端点不支持 stream=true，请去掉 stream 字段或改用异步端点」 |
| `async` / `?async=` / `X-Async` / `background` | 全部**静默忽略**（仍返回 200 同步结果） |
| 端点面（`/v1/models` + SPA bundle） | 只有 `/v1/audio/speech`，**没有异步 TTS 端点**（`/audio/speech/async` 等全 404） |

⇒ 墙钟 ≈ **48 ms/字**（克隆路径）/ 61 ms/字（预设音色路径），与音频时长无关。
⇒ **老代码把「音频时长」当成了「墙钟」**（250 字 → 音频 43.7s ⇒ 「占 60s 的 2/3」）
⇒ 于是只敢用 250 字 ⇒ 一篇 2544 字的稿子切成 **12 段**（生产 journal 实测）。

### 1.2 身份层：金标准 ECAPA（离线）

标定（同一上游、同一克隆源，ECAPA-TDNN `spkrec-ecapa-voxceleb`，整段余弦）：

| 组 | 余弦 |
|---|---|
| 同一人（克隆段 / 同音色另一次渲染） | **0.75 ~ 0.80** |
| 同一段文本重渲一次 | **0.93 ~ 0.95** |
| 换人（预设音色 `vivian` / `serena`） | **0.29 ~ 0.35** |

⇒ 分离带：**换人 ≤ 0.35，同一人 ≥ 0.75**，门禁阈值 **0.55**。

### 1.3 上游 `voice` 与 `ref_audio` 的语义（实测矩阵，9 个样本）

| 请求 | ECAPA vs 克隆源 | 结论 |
|---|---|---|
| `voice=uncle_fu`（无 ref）×3 | 0.747 / 0.742 / 0.755 | **`uncle_fu` 就是这个账号登记的婷婷音色** |
| `voice=vivian`（无 ref） | 0.329 | 换人 |
| `voice=serena`（无 ref） | 0.349 | 换人 |
| 克隆（无 voice） | 0.782 | 克隆源 |
| **克隆 + `voice=vivian`** | **0.772** | ⇒ **克隆模式下 `voice` 被忽略**（纯 vivian 只有 0.329） |
| 克隆 + `voice=uncle_fu` | 0.796 | 同上 |
| 无 voice 无 ref | 0.339 | 兜底路径是**另一个人** |

⇒ 生产配置 `openai_voice='uncle_fu'` **不是另一个人**；
⇒ 仓里「同一 voice 连发 3 次 = 3 个人」的说法**不成立**
（那是**从基频 165/188/105 推断**的，没有说话人嵌入支持；
`uncle_fu` 连渲 3 次的 ECAPA 互相 0.93~0.95，是同一个人）。

### 1.4 误判：截断阈值落在正常区间内部

老阈值 **6.8** 是 2026-10-24 在 **Qwen3-TTS-12Hz-1.7B-Base** 上标的
（那时正常 4.80~6.45 字/秒）。生产现在跑 **CustomVoice**，实测（当日，n=35+）：

| 样本 | 天然 cps |
|---|---|
| 250 字克隆块（n=20） | 5.15 ~ **9.65** |
| 700~900 字块（n=8） | 5.43 ~ 6.51 |
| 909~983 字块（n=6） | 5.56 ~ 6.49 |
| 短块 40~60 字（生产日志） | 6.56 ~ 9.40 |

⇒ 6.8 落进**正常区间内部** ⇒ 生产近 24h 触发 **107 次**
「OpenAITTS 分块被截断，二分重来」（块长 239~250 字，即**正常块**）
⇒ 每次自愈把一块二分 ⇒ **凭空多出 1~2 个接缝**。

⇒ 阈值重标为 **11.0**（对正常上界 9.65 留 14% 余量）。

### 1.4b 两种失败的量级对比（24h 生产 journal）

| 事件 | 次数（24h，83 篇文章） |
|---|---|
| 「分块被截断，二分重来」（**误判**） | **111** |
| 「分块超时，二分重来」（上游 504） | 6 |
| 熔断打开 | 1 |

⇒ **误判是上游超时的 18 倍** ⇒ 优先级明确：先修阈值，再谈块长。

### 1.5 音域 / 响度：真正的听感来源

生产 journal（24h，154 次音高对齐）：

```
f0_before 187.6 / 219.9 / 257.2  →  对齐到 219.7（±2.73 半音）
```

⇒ 音域对齐在跑，但把各段**分别移了最多 2.73 半音**（≈16% 音高）——
这本身就会听成「音色变了」。

本地实测（7 个克隆段）：

| 指标 | 拼接前 | 拼接后 |
|---|---|---|
| 段间基频中位数散布 | **9.5%** | 9.4%（本地未生效对齐） |
| 段间 RMS 散布 | **0.05 dB** | 0.01 dB |

⇒ **响度根本不是问题源**（0.05 dB 听不出来），
⇒ **音域漂移（9.5%）+ 11 个接缝**才是。

### 1.5b ⚠️ 2026-11-25 推翻：「音域漂移」不是听感来源，**移调**才是

上面这段结论（「音域漂移 + 接缝才是问题源」）**被实测推翻了一半**：
接缝是问题源，这半句成立；但**音域漂移本身不是**，
而且**为了消除它而做的移调，才是新的问题源**。

实测（当前上游 hub.tsingfly.com，ECAPA 身份层，样本 = 生产真实 3175 字稿）：

| | 音域散布 | 块间身份余弦 |
|---|---|---|
| 上游天然画出的音域差（同文重渲 3 次） | 8.3%（= 1.38 半音） | **0.972 ~ 0.985** |
| 用音域对齐抹平它（各块移 ±0.69 半音） | 1.9% | **0.867 ~ 0.940** |

⇒ **Δ = -0.105**：把音域拉齐了，音色反而更像「不同的人」。
⇒ 单块变调多少半音 ⇒ 身份掉多少（本地实测）：

| 位移 | 0.25 半音 | 0.5 | 1.0 | 1.5 | 2.0 | 3.0 |
|---|---|---|---|---|---|---|
| 身份余弦 | 0.995 | 0.983 | 0.939 | 0.879 | 0.811 | 0.732 |

⇒ **同样的音域差，用「自然渲染差异」表达只掉到 0.972，
用「变调」表达掉到 0.879 —— 变调比自然差异伤 3 倍。**

⇒ 契约改为：**音域对齐默认关闭**（`OPENAI_TTS_ALIGN_PITCH` 默认 `"0"`）。
⇒ 接缝处的音域跳变交给「**减少接缝**」解决（§2.1），不是交给逐块移调。

### 1.5c 顺带被否证的两条（2026-11-25）

* **「上下文续写」（拿上一段的输出当下一段的参考音）⇒ 否证**。
  实测声线**逐块崩塌**：各块与参考音的余弦 0.856 → 0.764 → 0.656 → **0.050** → **0.051**
  （第 4、5 块字面上就是换了个人），且同样字数产出的音频更长（帧数 445 → 775 → 807
  ⇒ 语速变慢）。
* **「跨块比基频散布」当判据 ⇒ 否证**。仓内既有结论（不同文本的固有音高差可达 13%）
  加上本轮噪声底（**同一段文本**重渲 4 次，median 散布 **14.0%**）⇒ 这个量
  区分不出任何东西。判据必须落在**身份层**（ECAPA）。


## 2. 契约

### 2.1 段长（结构层 —— 最有效的一招）

| 项 | 值 | 依据 |
|---|---|---|
| **内容完整性上限** | **1000 字**（代码常量 `openai._MAX_SAFE_CHUNK_CHARS`，两条路径都受约束） | 2026-11-26 标定：700→4块总 508.4s（cps 4.61）✅ / 1000→3块总 523.7s（cps 4.47）✅ / **1500→2块总 440.5s（cps 5.33）❌ 少 ~83s ≈ 370 字**；ASR 实证丢 related[2]+related[3]+insights[0] 共 ~397 字。已知上游截断点 1158 字 ⇒ 取 1000（留 14% 余量） |
| 克隆块长 | **1000 字**（`OPENAI_TTS_CLONE_CHUNK_CHARS`，代码默认；2026-11-26 由 1500 下调） | ⚠️ **2026-11-26 推翻 1500**：那次是「墙钟余量」论证（63.0s ≪ 300s 超时），但**墙钟不保证内容完整** ⇒ 端点行为与路径无关，克隆路径同样受 1000 上限约束 |
| 预设音色块长 | **700 字**（`OPENAI_TTS_CHUNK_CHARS`，生产 env；2026-11-26 由 1500 回滚） | 700 是 1000 上限内的保守值（4.61 字/秒实测正常）；1500 会静默丢内容 ⇒ **不能用** |
| 两条路径 | **互不夹**（2026-10-25 解耦） | 每字墙钟不同，用贵的预算限便宜的路径＝凭空砍一半余量 |
| **上游请求闸门** | 进程内，容量 **1**（`openai._upstream_slot`） | 上游串行处理 ⇒ 并发零吞吐收益，却会让请求**在上游**排队 → 撞它那条含排队时间的 60s 墙钟 |

⇒ 2500 字的稿子：**4 段**（接缝 3）。块数变多是要付的代价 ——
   预设音色路径下**接缝不再换人**（voice 是固定说话人，§2.5），
   而「丢内容」是直接的内容缺陷，两者量级完全不同。
⇒ ⚠️ **安全网只在 429/504 上是真的**（2026-11-26 更正）：分块重试 + 二分自愈能处理
   「上游报错/超时」，但**接不住静默截断** —— 截断后 cps 仍落在正常区间，
   `_assert_not_truncated` 不触发 ⇒ 块丢内容照样「成功」返回。
   ⇒ **静默截断的唯一有效防线是块长上限**（预防，不是检测）。

### 2.1.1 上游墙钟预算律（⚠️ 2026-11-25 修订：60s 墙钟在当前上游已不存在）

**旧律（2026-10-25，上游 tertu.cn）**：上游有一条**包含排队时间**的 60s 墙钟，
我们等不计入、上游等计入 ⇒ 闸门容量 = 1 ⇒ 单请求墙钟 = 字数 × 48ms × 负载系数，
800 字 ⇒ 45s ⇒ 对 60s 留 1.3 倍余量。

**当前实测（2026-11-25，上游 hub.tsingfly.com，克隆路径，生产真实 3175 字稿）**：

| 字数 | 墙钟 | 音频时长 | 语速(字/音频秒) |
|---|---|---|---|
| 800 | 34.5s | 115.5s | 6.93 |
| 1000 | 44.7s | 152.5s | 6.56 |
| 1200 | 51.6s | 173.6s | 6.91 |
| **1500（新）** | **63.0s** | **224.3s** | **6.69** |
| 1800 | 103.2s | 261.4s | 6.89 |
| 2000 | 77.7s | 274.0s | 7.30 |
| 2200 | 89.9s | 317.4s | 6.93 |
| 1400 / 1600 | — | — | **429「资源不足」**（上游负载敏感） |

⇒ **旧律的前提失效**：当前上游对 1500 字 63.0s、1800 字 103.2s、2200 字 89.9s
**全部返回 200** ⇒ 没有那条 60s 墙钟。
⇒ 新的预算分母是**我们自己的 httpx 读超时 300s**（`OPENAI_TTS_TIMEOUT`），
不是上游的墙钟。取 1500 字 ⇒ 按最差实测斜率（96.2s/1600 字 = 60ms/字）算，
余量 **4.8 倍**。
⇒ ⚠️ **上游是负载敏感的**：实测撞到 429「Tokenhub error: Too many requests.
  Current resources are insufficient」⇒ 大块长在有负载时更容易失败，
  而失败要重渲 + 退避 ⇒ **余量比那一点接缝收益更值钱**。
⇒ ⚠️ **「上游有 ~322s 音频上限」是错的**（2026-11-25 第一轮自己也这么以为）：
  同一份 2000 字文本，两次实测分别产出 **322.0s** 与 **274.0s**
  ⇒ 那是**抽样语速**的差别，不是上限。别拿它当依据。



### 2.2 截断判据

| 项 | 值 |
|---|---|
| 阈值 | **11.0 字/秒**（`_TRUNCATION_CHARS_PER_SEC`） |
| 分档 | **无** —— 实测 cps 与块长无关，只与文本内容有关 |
| 切不动的短块（< `_MIN_SPLIT_CHARS` = 12） | **告警并保留音频**，不上抛 |

⚠️ **「宁可误报」的取舍改成「误报不致命」**：老写法让短块误判直接抛异常
⇒ 整篇蒸馏失败（实测 47 字的块被判 9.40 字/秒 ⇒ 整篇挂掉）。
现在：切得动的照常自愈；切不动的保留那一小块。

⚠️ **已知能力边界**：速率判据只能筛「缺得很狠」的截断（缺 45% 以上）。
老阈值时代被当作「真截断」的样本（7.14~8.67）**今天在正常带内** ⇒
轻微截尾抓不到。这是已知边界，不是没测出来。

### 2.3 拼接口径

| 项 | 旧 | 新 | 理由 |
|---|---|---|---|
| 响度 | 每段强制拉到 −20 dBFS | **只修离群段 + 整篇统一归一**（死区 1 dB、增益封顶 6 dB） | 实测段间只差 0.05 dB，老做法几乎没修却把每段都重编码，还压掉段内动态、把安静段底噪拉起来 |
| crossfade | 300 ms | **100 ms**（`OPENAI_TTS_CROSSFADE_SEC`） | 300 ms 重叠＝两个独立渲染**同时发声 300 ms**，正是「好几种音色」的听感来源；业界也是「fade 要短」（长 fade 糊辅音） |
| 音域对齐 | 开着（死区 3%、封顶 3.5 半音） | 不变 | 它确实在消除 F0 漂移；但 ±2.73 半音的位移本身也有染色代价 —— 段数变少后需要移的量也更小 |

### 2.4 判据常量（`app/services/tts/consistency.py`）

⚠️ **2026-11-25：身份层三个常量按当前上游重新标定**（旧值来自旧上游，已失效）。

| 常量 | 值 | 层级 | 能否运行时算 |
|---|---|---|---|
| `ECAPA_SAME_MIN` | **0.85** | 身份 | ❌ 需 torch+speechbrain（离线审计） |
| `ECAPA_DIFF_MAX` | **0.70** | 身份 | ❌ |
| `ECAPA_THRESHOLD` | **0.78** | 身份 | ❌ |
| `PITCH_SPREAD_MAX` | 0.05 | 韵律 | ✅（但**只适用于同文重渲**） |
| `LOUDNESS_SPREAD_MAX_DB` | 1.0 | 电平 | ✅ |
| `MAX_SEGMENTS` | 4 | 结构 | ✅ |

新标定（当前上游，克隆源 = 婷婷 = 上游预设音色 `uncle_fu`）：

| 类别 | 实测区间 |
|---|---|
| 同一人（克隆块 vs 克隆源） | 0.857 ~ 0.931 |
| 同一人（不同文本的块 vs 块） | 0.931 ~ 0.978 |
| 同一人（同一段文本重渲两两） | 0.972 ~ 0.985 |
| 换人（上游预设音色两两 / vs 克隆源） | 0.357 ~ 0.697 |

⇒ 分离带 **[0.697, 0.857]**（中间是空的）⇒ 阈值取 0.78。
⇒ `DIFF_MAX` 从 0.35 放宽到 0.70：因为**两个不同的预设音色之间也能有 0.70**
（实测 `serena ↔ vivian` = 0.697）⇒ 旧值会把「换人」误判成「不确定」。

⚠️ **跨段比基频量到的是「文案差异」，不是「换没换人」**
（实测同篇 4 块差 17.8%，同文重渲只差 2.4%；2026-11-25 复测：同文重渲
median 散布 **14.0%**）⇒ 韵律层**只作参考，不作门禁**。

⚠️ **ECAPA 绝对阈值依实现而变**（F5-TTS 模型卡原话）⇒ 换模型/换上游/换版本
必须重新标定（2026-11-25 已经因为换上游重标过一次）。

### 2.4.1 ⚠️ 两个**测量单位**不能混用（2026-11-25 补）

上表的三个 ECAPA 常量标定在 **「整段渲染件 vs 整段」** 这个单位上
（一个 chunk 对一个 chunk / 对一个参考音）。
但排查存量音频时用的是 **「滑窗相邻余弦」**（同一段连续音频的两个 6s 切片）——
**这是另一个单位**，两者阈值**不可互换**。

同一天用**已知真值**把滑窗这条判据单独标定了（真值素材：
A 组 5 块同音色自然接缝、`control` 组不同预设音色）：

| 真值基准 | 滑窗相邻余弦最低 | 跌破 0.70 的窗口对 |
|---|---|---|
| 同一人（5 块自然接缝，硬拼） | 0.8478 | 0 / 227 |
| 同一人（5 块自然接缝，crossfade） | 0.8727 | 0 / 227 |
| 同一人（**单条自比，无接缝**） | **0.8227** | 0 / 89 |
| **换人**（uncle_fu + vivian，硬拼） | **0.5487** | 1 / 178 |
| 换人（uncle_fu + vivian，crossfade） | 0.5514 | 1 / 178 |

⇒ **滑窗判据的刻度**（与 2.4 的表**不是同一套**）：

| 滑窗相邻余弦 | 判定 |
|---|---|
| **≤ 0.70** | **真换人**（可靠：真值基准必然跌破，且只在跨接缝处出现） |
| 0.70 ~ 0.82 | 不确定（接近接缝或内容差异） |
| **≥ 0.82** | 同一人（同一人基准下界 0.8227） |

⚠️ **0.85 对滑窗偏严**：连「同一人单条自比」都只有 0.8227 ⇒ 用 0.85 判滑窗
会制造假阳性。反过来 0.70 对滑窗**可靠**（真换人必然跌破）。

⇒ **仓内目前没有混用**：`consistency.py` 的三个 ECAPA 常量只被离线审计脚本
（`scripts/check_tts_timbre_ecapa.py` 等）使用，那些脚本量的是**整段 vs 整段**；
运行时判据 `judge_article` 只碰电平层与段数层，**不碰 ECAPA**。
但这条区别必须写在这里 —— 后人拿 2.4 的常量去判滑窗值，会得到系统性偏严的结论。

### 2.4.2 ⚠️ 预设素材的滑窗口径再修正（2026-11-25 取证）

§2.4.1 的滑窗刻度（同一人 ≥0.82）标定于**克隆素材**（单块自比 min **0.8227**）。
**预设素材的同人变异更宽**，直接套这条刻度会**假红**：

决定性实验（生产 8 块预设渲染 P01~P08，`scripts/exp_tts_preset_stability.py`）：

| 量 | 实测 | 含义 |
|---|---|---|
| 整段两两（28 对） | min **0.8629** / med 0.9452 / max 0.9801 | 零对 ≤0.70、零对 <0.85 ⇒ 8 块全同一人 |
| 单块自比滑窗 min | 低到 **0.698**（P05） | 预设同人变异比克隆宽（克隆 0.8227） |
| P05 那个 0.698 dip | @158s，距接缝 260.5s 偏移 **-101.5s** | 在**块内部**，与接缝无关；孤立单对，前后立即恢复 0.93/0.97 |
| 接缝 ±4s 窗口对（7 条缝） | 全 ≥ **0.8519** | 真正接缝处无一换人 |
| P05↔P06 整段 | **0.9686** | 跨缝身份极高 |

⇒ **「拼接件全局滑窗 min ≥0.82」对预设素材口径误设**：它把**块内自然韵律变异**
（单块自比就有、距接缝很远、孤立单对）误判成接缝换人。0.82 下界是按克隆的紧变异标的。

⇒ **预设的正确接缝判据**（`exp_tts_preset_stability_judge.py` 判据2）：
1. **整段身份**：所有块两两 ≥ `ECAPA_SAME_MIN`(0.85)，无一对 ≤ `ECAPA_DIFF_MAX`(0.70)；
2. **接缝 ±4s 窗口对**：取窗口对**中点落在接缝时刻 ±4s** 的那些对，min ≥ 0.82（滑窗刻度）
   且无一对 ≤0.70。接缝时刻 = 前块时长。

全局滑窗 min 与单块自比包络仍打印作**诊断参照**（说明误设来源），**不作门禁**。
真换人的判别不变：连续多对压低 + 整段余弦掉进换人带（≤0.70）—— 块内孤立 dip 不是换人。

⚠️ 这条修正**不是放宽阈值让实验通过**：取证（单块自比就有 0.698、dip 距接缝 -101.5s、
孤立单对立即恢复、整段 0.9686）证明全局 min 量错了对象。判据必须打在**接缝所属的位置**，
与「断言口径打在判据所属层」同源。裁决落盘 `scripts/tts_preset_stability_2026-11-25/verdict.txt`。


## 2.5 根治：声明式预设音色 = 固定说话人（2026-11-25）

### 2.5.1 根因再深一层：克隆是逐请求概率性采样

§0.1 的「减少接缝」是**治标**：块长 250→1500 把接缝从 ~9 减到 1，**大幅降低但非归零**。
存量核验（根因文档 §1.16）首批重生成 18 篇里 **2 篇原本同一人被改坏**
（`art_1b7999b8` 0.8767→0.2427、`art_1a259c1a` 0.8851→0.6662）。机制（生产日志一手证据）：
18 篇全 `clone=on`、2 块（1 个接缝），零样本克隆**每块一次独立请求、各采一个接近参考音的人**，
接缝处两人是否一致是**概率事件**（本批 2/17 ≈ **12%** 抽到明显不同的人）。

⇒ 真正消除换人要**固定说话人**，不是「把 10 次抽奖减到 1 次」。

### 2.5.2 预设音色就是固定说话人（已证实，不需要微调/自建 GPU）

当前上游（hub.tsingfly.com，Qwen3-TTS-12Hz-1.7B-CustomVoice）的**预设音色**跨请求身份稳定：
不传 `ref_audio` ⇒ `_resolve_clone` 返回 None ⇒ `voice` 名生效（克隆模式上游忽略 voice）。

* **预设 `uncle_fu` = 婷婷本尊**：预设 vs 克隆源 ECAPA **0.8849**（落在同人带 0.857~0.931）
  ⇒ 切预设**不改变「谁在念」**，新旧文章兼容（§1.3 早已实测 uncle_fu 就是账号登记的婷婷）。
* **跨请求稳定**：§2.4.2 的 8 块实验，整段 28 对 min 0.8629、接缝 ±4s 全 ≥0.8519 ⇒ 固定说话人成立。
* **上下文续写已否证**（§1.5c）⇒ 不做；微调/自建 GPU 不需要（预设现成）。

### 2.5.3 设计：声明式（音色库的一列），不是全局开关

迁移 **0042** 给 `tts_voices` 加 `preset_voice String(64) NULL`：

* 某行声明 `preset_voice='uncle_fu'` ⇒ 它是上游预设（固定说话人），蒸馏走预设路径
  （`synthesize` 只带 voice、**不带 ref_audio/ref_text**），`applied=True`。
* NULL（默认）⇒ 零样本克隆音色，**既有行为零回归**。
* 婷婷声明 `preset_voice='uncle_fu'`；参考音频/文本**保留**（非 openai provider 回落克隆要用）。

**为什么不用全局开关**：溯源诚实无法闭合。全局开关一开，所有音色都走预设，但
`distilled_articles.tts_voice_id` 记的仍是音色库那行 —— 若那行其实是克隆音色，溯源就在说谎
（记了一个没参与合成的音色，BUG#8 的延伸）。声明式把「走不走预设」绑在**音色行自己**身上：
声明了预设 ⇒ 预设真被使用 ⇒ `applied=True` ⇒ 记 voice_id 诚实；没声明 ⇒ 走克隆 ⇒ 按克隆规则溯源。

**调用链落点**（`ai-service/agent/tools.py`）：
`use_preset = bool(resolved.preset_voice) and client.provider_name == "openai"`。
预设分支 `synthesize(script, voice=resolved.preset_voice)`、`applied=True`；
否则走既有克隆 overrides 逻辑（**一字未改**）。admin 试听（`tts_voice_router.admin_preview_voice`）
同走预设分支（试听=生产渲染）。

### 2.6 内容完整性（与音色并列的第二条判据，2026-11-26 新增）

**「一篇音频听起来是同一个人」和「这篇音频念的是稿里的全部内容」是两条独立的判据，
各有各的失效方式，必须各自有守卫。**

| 判据 | 问的问题 | 失效形态 | 能测出来的手段 | 测**不**出来的手段 |
|---|---|---|---|---|
| 音色（§2.4） | 像不像同一个人 | 段间换人 | ECAPA 整段互比 | —— |
| **内容完整性（本节）** | 念没念完稿子 | **静默丢整段** | **ASR 逐段对照** | 时长 / cps / 墙钟 / ECAPA |

**为什么必须单列**：音色判据对内容缺失**完全免疫** ——
2026-11-25 那篇丢了 397 字的音频，四分段 ECAPA 互比依然 min≈0.95（还是同一个人），
活体验证因此「通过」并放过了缺陷。**两条判据不能互相顶替。**

**静默截断的机制**（2026-11-26 / 11-27 两次生产实证）：
上游会**返回 HTTP 200、音频更短、看起来完全成功**（比 504 更危险）。
⇒ 墙钟余量、429/504 重试**测不出它**；`_assert_not_truncated` 原本也测不出（阈值 11.0）：
1484 字块被截掉 26% 后 cps=5.84，仍落在正常区间 5.15~9.65 内。

块长压到 **700** 之后，生产重生成 4 篇里**仍有 2 篇丢内容**
（ASR 逐段对照：稿里 ≈590 字在音频里消失；缺口集中在 chunk2 尾部）。
用**生产日志逐块算语速**（不依赖 ASR）定位到：

|---|---|---|---|---|---|

⇒ 真正的防线必须是**运行时检测 + 自愈**。

**决定性实验：截断是确定性还是偶发？**（`scripts/exp_tts_chunk_replay.py`，生产真上游）
把**同一段文本**（a7ebe143 chunk1）连渲 3 次 + 二分两半：

|---|---|---|---|---|---|

**防线（三道，都要）**

1. **预防：块长上限**（降概率，不是杜绝）
   代码常量 `app/services/tts/openai.py::_MAX_SAFE_CHUNK_CHARS = 1000`，
   **两条路径（普通/克隆）都受约束**；env 越界一律 clamp + `log.warning` 留痕。
   实测（生产真稿逐块合成 + ASR 块尾抽查）：700 → 4 块总 508.4s ✅ / 1000 → 3 块总 523.7s ✅
   / **1500 → 2 块总 440.5s ❌ 少 ~83s ≈ 370 字**；已知上游截断点 1158 字。
   ⚠️ **2026-11-27 已知它单独不够**（700 字块仍被截断两次）⇒ 下面两道是必须的。
2. **检测：运行时语速判据**（2026-11-27 重标定）
   `_assert_not_truncated` 的阈值**分档**：

   | 场景 | 阈值 | 依据 |
   |---|---|---|
   | 预设路径（clone=off，固定说话人）长块（≥150 字） | **6.0** | 干净样本健康带 **4.07~5.72**（n=33）；实测截断签名 5.81/8.14/9.44/19.97 |
   | 克隆路径（每次重采样说话人 ⇒ 带更宽；且 2026-11-25 起生产已停用） | 11.0 | 沿用旧档，不因预设路径收紧而被误伤 |
   | 短块（<150 字，语速被首尾留白主导，带宽 19.9%） | 11.0 | 短块沿用宽松档，admin 的 TTS 测试按钮不红 |

   ⚠️ **旧阈值 11.0 为什么这么松**：它的基线（"正常带 5.15~9.65"）**混进了被截断的样本** ——
   同一个 250 字块两次实测 5.96 与 9.65，而 9.65 正是"音频只剩一半"的语速签名（≈5.0×2）。
   ⇒ **坏统计量把防线抬高**：阈值取在污染后的上界之上 ⇒ 真截断（8.14/9.44/19.97）反而无人守。
   ⇒ 重标定脚本：`scripts/calibrate_tts_truncation_band.py`（生产日志 + 生产稿件重建样本）。
   ⚠️ **为什么宁可余量只 ~5% 也不放宽**：误报与漏报的代价**不对称** ——
   误报 = 多一次上游请求（自愈的同文本重渲，预设路径**不新增接缝**），
   漏报 = **把缺内容的音频发上线**。⇒ 取严。
   ⚠️ **已知能力边界**：丢 26% 的**轻截断**（cps 5.81）**抓不到**（5.81 < 6.0）——
   已显式钉在守卫 `test_轻截断是已知能力边界` 里，谁想收紧必须同时改契约与守卫。
   ⚠️ **健康上界 5.72 这个样本的标签存疑**：它出自「同一段文本重渲」实验，
   而该实验做完后稿件被重生成改写过 ⇒ 拿新稿对齐旧渲染，相似度失真 ⇒ **标注实验已作废**。
   5.72 若实为轻截断，健康上界就是 5.49、余量 +9.3%；两种情况下 6.0 都成立。
   ⇒ **教训**：标定样本必须**先冻结稿件再渲染**（否则对齐的是另一版稿）。
3. **自愈：同文本重渲优先**（2026-11-27 新增）
   检出截断 ⇒ **先同文本重渲一次**（上游异常是偶发的，命中率 3/3，且**不新增接缝**），
   仍截断才回落既有**二分自愈**。
   ⚠️ 克隆路径**不做**同文本重渲（每次请求重采样说话人 ⇒ 重渲会换人）。

   `scripts/exp_tts_chunk_integrity.py`（生产逐块合成 + 落盘 + 块尾 ASR 抽查）
