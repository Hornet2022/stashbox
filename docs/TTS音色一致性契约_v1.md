# TTS 音色一致性 · 契约 v1（2026-10-25）

> 状态：**已实现（后端）**，待上线 + 活体验证。
> 本文是「缝合定义」—— 判据、阈值、开关都写在这里，也写进代码常量。
> **任何一方想改数字，先改这里，再改代码**，别各自发明。

## 0. 一句话

**「一篇音频听出好几种音色」不是上游换了人，而是「段数太多 + 误判触发的额外切分 + 接缝重叠太长」三件事叠在一起。**

上游的说话人身份是**稳定的**（金标准 ECAPA 实测：克隆段与参考音余弦 0.75~0.80，
换人只有 0.29~0.35 —— 分得很开）。真正让人听出「好几种音色」的是**接缝**，
而接缝的数量被两件事放大：**块长太小** + **截断阈值误判引发的二分自愈**。

## 1. 证据（全部实测，2026-10-25）

### 1.1 上游能力：60s 墙钟是**端点**的，不是模型的

| 探测 | 结果 |
|---|---|
| 单次 250 字 | 200，墙钟 **12.1s** |
| 单次 800 字 | 200，墙钟 **31.8s** |
| 单次 1500 字 | 200，墙钟 **58.8s** |
| `stream: true` | **400**：「同步 /v1/audio/speech 端点不支持 stream=true，请去掉 stream 字段或改用异步端点」 |
| `async` / `?async=` / `X-Async` / `background` | 全部**静默忽略**（仍返回 200 同步结果） |
| 端点面（`/v1/models` + SPA bundle） | 只有 `/v1/audio/speech`，**没有异步 TTS 端点**（`/audio/speech/async` 等全 404） |

⇒ 墙钟 ≈ **48 ms/字**（克隆路径）/ 61 ms/字（预设音色路径），与音频时长无关。
⇒ **老代码把「音频时长」当成了「墙钟」**（250 字 → 音频 43.7s ⇒ 「占 60s 的 2/3」）
⇒ 于是只敢用 250 字 ⇒ 一篇 2544 字的稿子切成 **12 段**（生产 journal 实测）。

### 1.2 身份层：金标准 ECAPA（离线）

标定（同一上游、同一克隆源，ECAPA-TDNN `spkrec-ecapa-voxceleb`，整段余弦）：

| 组 | 余弦 |
|---|---|
| 同一人（克隆段 / 同音色另一次渲染） | **0.75 ~ 0.80** |
| 同一段文本重渲一次 | **0.93 ~ 0.95** |
| 换人（预设音色 `vivian` / `serena`） | **0.29 ~ 0.35** |

⇒ 分离带：**换人 ≤ 0.35，同一人 ≥ 0.75**，门禁阈值 **0.55**。

### 1.3 上游 `voice` 与 `ref_audio` 的语义（实测矩阵，9 个样本）

| 请求 | ECAPA vs 克隆源 | 结论 |
|---|---|---|
| `voice=uncle_fu`（无 ref）×3 | 0.747 / 0.742 / 0.755 | **`uncle_fu` 就是这个账号登记的婷婷音色** |
| `voice=vivian`（无 ref） | 0.329 | 换人 |
| `voice=serena`（无 ref） | 0.349 | 换人 |
| 克隆（无 voice） | 0.782 | 克隆源 |
| **克隆 + `voice=vivian`** | **0.772** | ⇒ **克隆模式下 `voice` 被忽略**（纯 vivian 只有 0.329） |
| 克隆 + `voice=uncle_fu` | 0.796 | 同上 |
| 无 voice 无 ref | 0.339 | 兜底路径是**另一个人** |

⇒ 生产配置 `openai_voice='uncle_fu'` **不是另一个人**；
⇒ 仓里「同一 voice 连发 3 次 = 3 个人」的说法**不成立**
（那是**从基频 165/188/105 推断**的，没有说话人嵌入支持；
`uncle_fu` 连渲 3 次的 ECAPA 互相 0.93~0.95，是同一个人）。

### 1.4 误判：截断阈值落在正常区间内部

老阈值 **6.8** 是 2026-10-24 在 **Qwen3-TTS-12Hz-1.7B-Base** 上标的
（那时正常 4.80~6.45 字/秒）。生产现在跑 **CustomVoice**，实测（当日，n=35+）：

| 样本 | 天然 cps |
|---|---|
| 250 字克隆块（n=20） | 5.15 ~ **9.65** |
| 700~900 字块（n=8） | 5.43 ~ 6.51 |
| 909~983 字块（n=6） | 5.56 ~ 6.49 |
| 短块 40~60 字（生产日志） | 6.56 ~ 9.40 |

⇒ 6.8 落进**正常区间内部** ⇒ 生产近 24h 触发 **107 次**
「OpenAITTS 分块被截断，二分重来」（块长 239~250 字，即**正常块**）
⇒ 每次自愈把一块二分 ⇒ **凭空多出 1~2 个接缝**。

⇒ 阈值重标为 **11.0**（对正常上界 9.65 留 14% 余量）。

### 1.4b 两种失败的量级对比（24h 生产 journal）

| 事件 | 次数（24h，83 篇文章） |
|---|---|
| 「分块被截断，二分重来」（**误判**） | **111** |
| 「分块超时，二分重来」（上游 504） | 6 |
| 熔断打开 | 1 |

⇒ **误判是上游超时的 18 倍** ⇒ 优先级明确：先修阈值，再谈块长。

### 1.5 音域 / 响度：真正的听感来源

生产 journal（24h，154 次音高对齐）：

```
f0_before 187.6 / 219.9 / 257.2  →  对齐到 219.7（±2.73 半音）
```

⇒ 音域对齐在跑，但把各段**分别移了最多 2.73 半音**（≈16% 音高）——
这本身就会听成「音色变了」。

本地实测（7 个克隆段）：

| 指标 | 拼接前 | 拼接后 |
|---|---|---|
| 段间基频中位数散布 | **9.5%** | 9.4%（本地未生效对齐） |
| 段间 RMS 散布 | **0.05 dB** | 0.01 dB |

⇒ **响度根本不是问题源**（0.05 dB 听不出来），
⇒ **音域漂移（9.5%）+ 11 个接缝**才是。

## 2. 契约

### 2.1 段长（结构层 —— 最有效的一招）

| 项 | 值 | 依据 |
|---|---|---|
| 克隆块长 | **800 字**（`OPENAI_TTS_CLONE_CHUNK_CHARS`） | 墙钟 31.8s → 单请求 45s（含 1.4 倍负载）< 60s ✓ |
| 预设音色块长 | 700 字（`OPENAI_TTS_CHUNK_CHARS`） | 61 ms/字 → 43s（余量更紧） |
| 两条路径 | **互不夹**（2026-10-25 解耦） | 每字墙钟不同，用贵的预算限便宜的路径＝凭空砍一半余量 |
| **上游请求闸门** | 进程内，容量 **1**（`openai._upstream_slot`） | 上游串行处理 ⇒ 并发零吞吐收益，却会让请求**在上游**排队 → 撞它那条含排队时间的 60s 墙钟 |

⇒ 2544 字的稿子：**12 段 → 4 段**（接缝 11 → 3）。
⇒ **安全网还在**：撞墙钟（504）或被截断时，二分自愈会把那块拆小重渲。

### 2.1.1 上游墙钟预算律（为什么 800 字是安全的）

上游的两条实测性质合在一起，决定了块长上限：

1. 上游**串行处理**（2026-10-21 实测：并发 1/2/4 的总耗时 54.2 / 51.1 / 53.4s
   ⇒ **并发对它零吞吐贡献**）。
2. 上游那条 **60s 墙钟包含它在队列里等的时间**（实测：把上游打满后，
   **80 字**的请求连续 504 —— 80 字的推理只要 ~4s，不可能自己算到 60s）。

⇒ **排队必须发生在我们这边**：我们等 → 不计入上游的 60s（我们的 timeout 是 300s）；
上游等 → 计入它那条 60s → 直接变 504。
⇒ 闸门容量 = 1（上游一次只处理一个，并发只增加排队、不增加吞吐）。

于是单请求的上游墙钟 = 字数 × 48 ms/字 × 负载系数（实测 1.4）：

| 字数 | 单请求墙钟 | 对 60s 的余量 |
|---|---|---|
| 250（旧） | 17s | 3.5x |
| **800（新）** | **45s** | **1.3x** |
| 1000 | 56s | 1.07x ⇒ 不取 |

⚠️ **没有闸门时 800 字是不安全的**：两个并发作业 ⇒ 第二个请求在上游排 45s
⇒ 90s ⇒ 必 504（2026-10-25 实测：探针与生产同时打上游，781 字的块就 504 了）。
⇒ **闸门与块长是配套的**，改一个就要重算另一个。

### 2.2 截断判据

| 项 | 值 |
|---|---|
| 阈值 | **11.0 字/秒**（`_TRUNCATION_CHARS_PER_SEC`） |
| 分档 | **无** —— 实测 cps 与块长无关，只与文本内容有关 |
| 切不动的短块（< `_MIN_SPLIT_CHARS` = 12） | **告警并保留音频**，不上抛 |

⚠️ **「宁可误报」的取舍改成「误报不致命」**：老写法让短块误判直接抛异常
⇒ 整篇蒸馏失败（实测 47 字的块被判 9.40 字/秒 ⇒ 整篇挂掉）。
现在：切得动的照常自愈；切不动的保留那一小块。

⚠️ **已知能力边界**：速率判据只能筛「缺得很狠」的截断（缺 45% 以上）。
老阈值时代被当作「真截断」的样本（7.14~8.67）**今天在正常带内** ⇒
轻微截尾抓不到。这是已知边界，不是没测出来。

### 2.3 拼接口径

| 项 | 旧 | 新 | 理由 |
|---|---|---|---|
| 响度 | 每段强制拉到 −20 dBFS | **只修离群段 + 整篇统一归一**（死区 1 dB、增益封顶 6 dB） | 实测段间只差 0.05 dB，老做法几乎没修却把每段都重编码，还压掉段内动态、把安静段底噪拉起来 |
| crossfade | 300 ms | **100 ms**（`OPENAI_TTS_CROSSFADE_SEC`） | 300 ms 重叠＝两个独立渲染**同时发声 300 ms**，正是「好几种音色」的听感来源；业界也是「fade 要短」（长 fade 糊辅音） |
| 音域对齐 | 开着（死区 3%、封顶 3.5 半音） | 不变 | 它确实在消除 F0 漂移；但 ±2.73 半音的位移本身也有染色代价 —— 段数变少后需要移的量也更小 |

### 2.4 判据常量（`app/services/tts/consistency.py`）

| 常量 | 值 | 层级 | 能否运行时算 |
|---|---|---|---|
| `ECAPA_SAME_MIN` | 0.75 | 身份 | ❌ 需 torch+speechbrain（离线审计） |
| `ECAPA_DIFF_MAX` | 0.35 | 身份 | ❌ |
| `ECAPA_THRESHOLD` | 0.55 | 身份 | ❌ |
| `PITCH_SPREAD_MAX` | 0.05 | 韵律 | ✅（但**只适用于同文重渲**） |
| `LOUDNESS_SPREAD_MAX_DB` | 1.0 | 电平 | ✅ |
| `MAX_SEGMENTS` | 4 | 结构 | ✅ |

⚠️ **跨段比基频量到的是「文案差异」，不是「换没换人」**
（实测同篇 4 块差 17.8%，同文重渲只差 2.4%）⇒ 韵律层**只作参考，不作门禁**。

⚠️ **ECAPA 绝对阈值依实现而变**（F5-TTS 模型卡原话）⇒ 换模型/换上游/换版本
必须重新标定。

## 3. 被否证的做法（留档，别再做）

| 做法 | 否证证据 |
|---|---|
| 自写 MFCC 余弦当音色判据 | 与 ECAPA 的 Spearman ρ = **0.078**（87 对样本）；窗间距离 0.32 **大于**分段间 0.16 ⇒ 被**内容**主导。模块已删除 |
| 「同一 voice 连发 3 次 = 3 个人」 | ECAPA 互相 0.93~0.95 = 同一个人。原说法是从基频推断的 |
| 「hosted 端点不认 voice 名」 | 端点**认**（`voice=vivian` 明显换人）；是**克隆模式下忽略 voice** |
| 「按块长分档设截断阈值」 | 实测 cps 与块长无关 |
| 「逐段强制等电平」 | 实测段间只差 0.05 dB；老做法还压动态、拉底噪 |
| 「并发能提上游吞吐」 | 实测并发 1/2/4 总耗时 54.2/51.1/53.4s ⇒ 零收益，只有排队 |
