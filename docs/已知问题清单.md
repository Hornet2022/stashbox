# 当前已知问题清单

> 建立日期：2026-10-25
> 覆盖范围：`stashbox`（后端）、`stashbox-admin-web`（管理后台）、`stashbox-android`（安卓端）三仓
> 口径：**只写现在还成立的问题**，每条都带「怎么复现 / 怎么证据」；已修的不留在这里
> （历史结论见 `docs/archive/` 下的归档审计）

---

## 这份清单为什么存在

之前的两份审计（`docs/archive/cp10.9-product-audit_2026-09-20.md`、
`stashbox-android/docs/archive/MVP闭环审计_2026-09-22.md`）都把**已修**的问题
写成 ❌，读者照着排期会做无用功 —— 而反过来，更危险的是：**没有任何一份文档
在记录「现在还有什么没修」**。

所以这份清单的规矩是：

1. **每条都要能复现**，写不出复现步骤的，不算已知问题；
2. **每条都标影响面**（挡住了内测 / 只影响体验 / 只是技术债）；
3. **挡住了内测的排在最前面**，并写清楚「解开的条件」。

---

## 一、挡住了内测的（必须解）

### K-01 · 真机 7 项验收没跑过：debug 包装不上（设备级授权）

**现象**

```
$ adb install -r app/build/outputs/apk/debug/app-debug.apk
Failure [INSTALL_FAILED_USER_RESTRICTED: Install canceled by user]
```

MIUI（Redmi K40）默认禁止 adb 侧静默安装。已尝试并**确认无效**的开关：

| 尝试 | 结果 |
|---|---|
| `settings put global adb_install_need_confirm 0` | 无效 |
| `settings put global install_non_market_apps 1` | 无效 |
| `settings put global user_setup_complete 1` | 无效 |
| `settings put global verifier_verify_adb_installs 0` | 无效 |
| `settings put global package_verifier_enable 0` | 无效 |
| `settings put secure install_non_market_apps 1` | 无效 |
| `settings put global install_packages 1` | 无效 |
| `adb shell pm install -r -t /data/local/tmp/x.apk` | 无效（与流式安装同一条限制） |

**根因**：MIUI 的「开发者选项 → USB 安装 / USB 调试（安全设置）」是**机主本人**
在手机上开的开关，adb 侧改不了。

**影响**：跨端 UI 用例（锁屏控制 / 身份隔离 / 订阅取消 / 全屏续播 / D9 回跳 / 列表标题）
**从未在真机上自动验证过**。目前的做法是：e2e 前置**自证**条件，不满足就**显式 skip**
并写清原因（见 `stashbox-admin-web/e2e/cross-device.spec.ts`）。

**解开条件**：机主在手机上开「开发者选项 → USB 安装（或 USB 调试（安全设置））」，
并当场确认安装弹窗。debug 包 applicationId = `com.tingxia.audio.debug`，
**与真机上已有的 release 包 `com.tingxia.audio` 不冲突**，可并存。

**进展（2026-10-25 本轮）**：机主决定**本轮不装**，真机验收留到下次。
为下次省一步，debug 包已经推到手机的「下载」目录：
`/sdcard/Download/stashbox-debug.apk`（构建时后端地址已指向隔离栈
`http://127.0.0.1:18100/`）⇒ 下次只要在手机上点确认安装即可，
不用重新构建、重新推送。

**影响面**：挡住真机验收（6/7 项）。

### K-02 · 真机上装的是 release 包，连的是生产后端

**现象**

```
$ adb shell pm list packages | grep tingxia
package:com.tingxia.audio          # 无 .debug 后缀
$ adb shell dumpsys package com.tingxia.audio | grep flags
flags=0x0                          # 不可调试
```

release 变体的 `apiBaseUrl` 指向 `https://api.stashbox.cn`（生产）。

**影响**：**在真机上跑 e2e 会打到生产数据**。这是本项目明确禁止的
（e2e 必须打隔离栈 `:18100-18103` + `stashbox_e2e` 库）。

**解开条件**：装上 debug 包（K-01），并用
`./gradlew :app:assembleDebug -PapiBaseUrl=http://127.0.0.1:18100/ -PfallbackApiBaseUrl=http://127.0.0.1:18100/`
构建 + `adb reverse tcp:18100 tcp:18100`。

**配套改动（已做）**：`e2e/android.ts` 改成**探测**包名（`PKG_CANDIDATES`）而不是写死
`com.tingxia.audio.debug`；`cross-device.spec.ts` 加「后端一致性」前置 ——
release 变体连生产时**显式 skip** 并说明原因，而不是打生产。

**当前的实际 skip 理由**（2026-10-25 实测输出）：

```
真机上的 App 不是指向隔离后端（判定=production，需要 debug 变体 + adb reverse tcp:18100），跳过跨端用例
```

⇒ 这两条 skip 是**有信号的**：它明确说「缺的是 debug 变体」，而不是一句
含混的「设备有问题」。

**影响面**：挡住真机验收；不挡住其它验收。

### K-03 · D9 夹具的假 URL 必然 502（不是产品 bug）

**现象**：e2e 里 D9 用 `https://mp.weixin.qq.com/s/<假 id>` 建文章 ⇒ 后端返回 502。

**根因**：D9 自 2026-10-03 改成「**先抓后扣**」（先抓正文、抓成功才扣配额），
假 URL 抓不到正文 ⇒ 正确地报「抓取失败」。**后端行为是对的，是夹具不成立。**

**解开方式（已做）**：新增 e2e 专用 mock 抓取器
（`backend/content-service/fetchers/e2e_mock.py`，开关 `STASHBOX_E2E_FETCH_MOCK=1`）。
mock 模式**只装** wechat / generic 两个 fetcher ⇒ **不可能发出任何真实请求**
（连 github 域名也返夹具，有回归测试守着）。

⚠️ 硬门控：`STASHBOX_E2E_FETCH_MOCK=1` 与 `ENVIRONMENT=prod` 同时出现会**直接抛错**。

**影响面**：只影响 e2e，已解。

## 二、影响体验 / 运营的（不挡内测，但要排期）

### K-04 · `POST /api/v1/events/collect` 的 `article_id` 是 int，与真实 id 不兼容

**现象**：后端 `EventCollectRequest.article_id: Optional[int]`
（`backend/common/event_collect.py:46`），而真实文章 id 是
`art_<24位十六进制>` **字符串**（`backend/content-service/main.py:225`）。

⇒ 带 `article_id` 顶层字段上报会被 pydantic 判类型不匹配 → **422** → 事件静默丢失。

**当前绕法**：安卓端把 article id 放进 `properties`（JSONB，无类型约束）。
已加注释 + 契约测试（`EventReporterTest` 钉住 JSON 键名）。

**正解**：改后端 schema（`article_id: Optional[str]`）+ 迁移。**本轮未做**，
因为改的是对外契约，且 `track()` 那边 `article_id` 本来就是 `str`。

**影响面**：客户端上报能过；但后台**按 article_id 聚合埋点**暂时做不到。

---

### K-05 · 月留存的「活跃」只能从埋点表反推（`users.last_active_at` 那一列不存在）

**现象**：`content-service/admin_router.py:1790` 写明
「last_active_at 本仓库 users 表未建该列（v1 §4.2.1 未列），列位保留但恒为空」。

⇒ 唯一真实存在的活跃来源是**埋点表 `feedback`**。
本轮新增 `backend/common/retention.py`：
活跃 = 自然月内任意一条埋点且 `user_id > 0`（`user_id=0` 是匿名上报约定）；
分母 = 上月活跃，分子 = 两月交集。

**口径陷阱（已处理）**：分母为 0 时 `rate` 是 **None** 而不是 0 ——
「0% 留存」和「没有样本」是两回事。

**影响面**：口径可用；但**匿名用户（未登录）不计入留存**，
内测期若测试员不登录会低估。

---

### K-06 · 微信 OAuth 仍未接入（AppID 未申请）

登录是「本机 code 派生独立测试账号」的占位实现（`ui/screens/LoginScreen.kt`）。
release 包只有一条登录路径，dev 联调入口只在 debug 包渲染。

**影响面**：内测可用（每人独立账号），但**不能上公网给真实用户**。

---

### K-07 · 生产剪藏**剪不动**动态渲染 / 需要登录的页面

`STASHBOX_FETCH_BROWSER_TIER=0`（chromium RSS 300MB+ vs content-service 的
MemoryMax 224MB，开浏览器通道等于埋 OOM）⇒ 生产只走 http 通道。

实测 `https://example.org/` 就是这类：http 通道报 `no article content extracted`，
靠升级 browser 才成功，而 browser 通道在生产是关的。

用户侧文案已按两类成因改写（`fetchers/__init__.py` 的 `_FETCH_ERROR_USER_MESSAGE`），
但**能力本身没有**。

**影响面**：剪藏成功率。这是内测反馈里最可能冒出来的一类。

---

### K-08 · 管理后台的 admin stats 走 30s Redis 缓存

`ADMIN_STATS_TTL = 30`（`backend/content-service/admin_router.py:2076`）。
⇒ 改了埋点口径 / 刚上报完事件，**后台最多要等 30s** 才看得到。

**影响面**：调试时的「我明明上报了怎么没有」类困惑。

## 三、技术债（不挡内测，但别忘了）

### K-09 · e2e mock 模式只覆盖 wechat / generic 两种抓取形态

mock 模式只装带 transport 注入点的两个 fetcher ⇒
**GitHub / 抖音 / PDF 的抓取在 e2e 里没有覆盖**。

这是**刻意**的取舍：少装三个换来「mock 模式下不可能有任何真实请求」这条硬保证。

**影响面**：e2e 覆盖有缺口。

### K-10 · 安卓 debug 包与 release 包 applicationId 不同，可同时装在一台机上

`com.tingxia.audio.debug` vs `com.tingxia.audio`。
好处是不冲突；坏处是**真机上同时存在两个「听匣」图标**，人工验收时容易点错。

**影响面**：人工验收时的操作风险，不是产品缺陷。

### K-11 · 新增的两个客户端指标**只过了单测，没在真机上验过**

`app_first_frame`（首屏）与 `audio_play_start.duration_ms`（音频启动）
本轮是**新加**的，端到端只到「单测覆盖了接线与格式」为止 ——
真机上的实际数值、埋点是否真的落库，**尚未验证**。

**解开条件**：K-01/K-02 解开后，装 debug 包跑一次，
在 `GET /api/v1/admin/stats` 或直接查 `feedback` 表确认落库。

**服务端侧已经验过的部分**（2026-10-25）：后端端点本身是真通的 ——
隔离栈上实测 `POST /api/v1/events/collect` 返回 `{"ok":true,"event_id":724}`，
`GET /api/v1/admin/stats` 返回 200 且带 `retention` 字段。
**没验的是安卓端发出去的那一条**（客户端是否会真的调、字段对不对得上）。

**影响面**：指标可信度。这是本清单里**最容易被误当成「已完成」**的一条。

### K-12 · e2e 需要外部隔离栈，跑之前得先起

e2e 打的是 e2e 专用后端（`stashbox_e2e` 库 / redis db 14 / `:18100-18103`），
不是本机开发栈。起法见 `stashbox-admin-web/e2e-backend.sh`。

**影响面**：跑 e2e 的前置条件。

## 四、明确**不是**问题的几件事（避免重复排查）

| 现象 | 真相 |
|---|---|
| e2e 里 D9 建文章返回 502 | 后端「先抓后扣」的正确行为，夹具问题不是产品 bug（K-03） |
| admin-web 的 articles 用例找不到按钮 | 测试断言写的是**产品里不存在的 aria-label**（产品用「重试 / 失效音频 / 删除」按钮文案），已改断言 |
| tags 用例报缺标签 | 种子数据只种了 4 个系统标签，夹具要一个非系统标签，已补 `e2e-custom` |
| `users.last_active_at` 是空的 | 那一列**根本没建**（K-05），不是「有定时任务没跑」 |
| 后台看不到刚上报的埋点 | 30s 缓存（K-08） |

## 维护规矩

1. 修掉一条就从这里**删掉**它，并在归档审计里留一句结论；
2. 新发现的先写「怎么复现」，写不出复现步骤的先别放进来；
3. 这份清单**不替代**代码里的注释 —— 它的作用是「跨仓、当前状态」，
   单点的「为什么这么写」仍然写在代码旁边。
